# Skaro 2.2.20

Дата подготовки: 05.11.2026. Bundle и отображаемая версия: `2.2.20`.

## Исправление

Повторное открытие завершённой задачи или задачи с готовой интеграцией локальных
изменений могло запускать цикл `task.open → idle → project.changed → task.open`.
Каждое уведомление также отменяло и повторно запускало индексацию графа.
Отсутствующая runtime-запись теперь правильно считается состоянием `idle`:
повторная установка не пишет в БД и не отправляет события изменения.
Настоящие смены состояния и владельца активного запуска сохраняются. UI не изменён.

## Проверки

- Production-сборка, desktop main TypeScript, целевые ESLint/Prettier прошли.
- Старое условие проваливает два регрессионных сценария, включая попытку лишней
  записи в реальную БД, открытую readOnly. Исправление проходит три целевых теста.
- На реальном Cat-pilot: 1000 повторных установок `idle` для T-005 — 0 изменений
  runtime и 0 попыток записи. Подмена backend и проектных данных не применялась.
- В настоящем Electron со scope Cat-pilot: 25 открытий завершённой T-001 и ещё
  5 секунд наблюдения — 0 `project.changed`, 0 `task.changed`, ошибок renderer нет.
  Сохранённый снимок окна проверен визуально. Глобальные вкладки не восстанавливались.
- Изменённые файлы не превышают 300 строк; runtime-переход вынесен в отдельный модуль.

## Разрешение на выпуск

Владелец явно разрешил для 2.2.20 полный штатный CI/release suite с существующими
изолированными fixtures и HTTP test servers, а также переиспользование принятой
проверки неизменённых агентов из 2.2.19. Новые canary/model проверки не заявляются.
Pins агентов, SDK, адаптеры и lockfile не меняются.

Выпуск выполняется по [контракту обновлений](updates.md), с `check_scope=full`,
`test_fixtures_allowed=true`, `agents_verified=true`, после обязательных проверок PR.
Шесть установщиков публикуются штатным workflow; описание должно содержать
таблицу прямых ссылок Windows/macOS/Linux × x64/arm64 именно для 2.2.20.
