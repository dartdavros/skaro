# Спецификация и C4 в общем чате

По поручению владельца от 15.11.2026 сообщение об ожидающем согласовании
должно соответствовать настоящей карточке в общем чате проекта.

- Исходный эпизод подтверждён настоящим журналом общего чата: пакет успешно
  прошёл `pending → accepted → applied`, а через 292 секунды агент сообщил
  устаревшее ожидание. Между применением и финалом агент не получил входного
  обновления. Карточка была закрыта после применения правильно.
- Подтверждённое применение, отказ или ошибка применения передаются работающему
  агенту как служебное обновление контекста и сохраняются для следующего сообщения.
  Обновление ограничено активным ходом: гонка с его завершением не запускает новый
  ход и не возобновляет остановленный чат. Служебный input сохраняется в сырой
  истории и не создаёт пользовательский пузырь в ленте.
- Перед утверждением в финале, что пакет всё ещё ожидает решения, агент читает
  актуальный `get_c4_context`. Старый ответ `pending` не является текущим статусом.
- Уточнение спецификации и C4 создаётся единым `propose_c4`. Диагностика
  `get_c4_context` и отказ отдельного `propose_spec` карточку не создают.
- Успешный ответ содержит `packageId`, `state: pending` и владельца решения.
  До такого ответа агент не сообщает, что пакет ожидает решения в карточке.
- Контекст включает владельца каждого пакета и `inCurrentConversation`.
  Предложение другого чата или задачи не считается карточкой текущего чата.
  Все ожидающие пакеты включаются независимо от возраста.
- Публикация немедленно обновляет ленту и открытый общий чат. При завершении
  хода контроллер сверяет сохранённые пакеты с лентой и восстанавливает пропуски.
  Восстановление не задерживает событие завершения агента; ошибка хранилища
  отображается отдельно и не превращает успешный ход в неуспешный.
- При чтении, включая кеш и пагинацию, открытые решения дополняются из
  долговечного хранилища, включая последующие `history.changed` открытого чата.
  Решённое состояние хранилища закрывает устаревшее
  ожидание; чужие предложения в общий чат не переносятся.
- Карточка использует существующую закреплённую область над вводом. Финальное
  сообщение, список файлов, новые сообщения и страницы истории её не скрывают.

Сохраняется [общий контракт действий в ленте](agent-output.md).
Отдельный UI и автоматическое согласие владельца не добавляются.

Доставка учитывает возможности адаптеров. Codex связывает steering с текущим
native turn; встроенный агент принимает его только до закрытия активного model
turn. Claude получает документированный SDK input с `shouldQuery: false`:
он сохраняет контекст для следующего запроса и не запускает новый ход при гонке
с завершением. SDK не гарантирует перегенерацию уже идущего ответа Claude.
Поэтому актуальное чтение C4 перед финальным утверждением обязательно для всех
агентов, а сохранённые заметки доставляются также со следующим сообщением владельца.
