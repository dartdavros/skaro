# Skaro v2 — продуктовая концепция

## Что такое Skaro

Skaro — open-source десктоп-приложение для управления разработкой с помощью AI-агентов.

Skaro сам не пишет код. Код пишут coding-агенты, которые уже установлены у пользователя: **Claude Code** и **Codex**. Skaro отвечает за всё, что вокруг кода:

- проекты и их документацию (бриф, архитектура, ADR, спецификации) — в том числе перенесённую из того, что у пользователя уже есть;
- план разработки — этапы и задачи с зависимостями;
- запуск агентов на задачи, в том числе параллельно;
- наблюдение за работой агента в реальном времени;
- безопасное слияние результата в основную ветку.

Формула: **агент пишет код, Skaro держит проект под контролем.**

## Почему так

Версия v1 была построена в период, когда полноценных coding-агентов ещё не было, поэтому Skaro сам собирал контекст, вызывал модели через BYOK и генерировал файлы по фазам. Сейчас Claude Code и Codex делают этот цикл (прочитать проект → изменить → запустить → исправить) лучше, чем может сделать сторонний инструмент.

При этом у агентов нет того, что было сильной стороной Skaro:

- долгоживущего контекста проекта — архитектуры, решений, правил;
- плана, разбитого на этапы и задачи с зависимостями;
- обзора «что сделано, что в работе, что ждёт меня» по всем проектам сразу;
- управляемого параллельного выполнения нескольких задач.

Skaro v2 соединяет эти две половины.

## Для кого

**Сейчас:** разработчик-одиночка, который работает с подпиской Claude и/или ChatGPT и хочет вести несколько проектов и несколько задач параллельно, не теряя контроль.

**Позже:** команды и компании — через платный Skaro Cloud (см. ниже).

## Принципы

1. **Просто для пользователя.** Пользователь видит проекты, документы, задачи, их статусы и вывод агента. Никаких обязательных фаз и ритуалов.
2. **Максимальная гибкость.** Агент, модель и режим работы выбираются для каждой задачи. Все артефакты — обычные Markdown-файлы, которые можно править руками.
3. **Безопасно по умолчанию.** Агент работает в изолированной копии (worktree). В основную ветку ничего не попадает без явного подтверждения пользователя.
4. **Прозрачно.** Видно, что делает агент, какие файлы меняет, какие команды запускает, чем закончилось.
5. **Локально.** Всё работает на машине пользователя, без обязательного облака и регистрации.
6. **Контекст рядом с кодом.** Документация и задачи лежат в репозитории (`.skaro/`) и версионируются вместе с кодом. Агенты видят их и без Skaro.

## Основные понятия

| Понятие | Что это |
|---|---|
| **Проект** | Папка с git-репозиторием, в которой есть `.skaro/`. |
| **Бриф** | Что строим, для кого, зачем, границы (что входит и не входит). |
| **Архитектура** | Как устроена система: компоненты, стек, потоки данных, а также раздел «Правила и ограничения», которым обязан следовать агент. |
| **ADR** | Запись об архитектурном решении: контекст, решение, последствия, статус. |
| **Спецификация** | Что именно делает функция: проблема, сценарии, пронумерованные требования, что не входит, открытые вопросы. Статусы как у ADR. Живой документ: описывает, как функция работает сейчас. Задачи ссылаются на спецификацию, которую реализуют. |
| **Импорт документации** | Однократный перенос документации пользователя (любая папка, файлы, архив, в любом формате) в формат Skaro. Выполняет агент, результат подтверждает пользователь. |
| **Документы** | Любые дополнительные Markdown-документы проекта (требования, заметки, исследования). |
| **Этап** | Крупная часть проекта с целью и критерием готовности. |
| **Задача** | Единица работы для агента: цель, критерии приёмки, зависимости. Принадлежит этапу. |
| **План** | Не отдельный документ, а вид: этапы по порядку, задачи внутри, связи зависимостей. |
| **Запуск** | Одна попытка выполнения задачи агентом. У задачи может быть несколько запусков. |
| **Чат** | Обсуждение с агентом без изменения кода. Бывает на уровне проекта и на уровне задачи. |

## Основной сценарий

1. **Создание проекта.** Пользователь создаёт новую папку или открывает существующую.
2. **Обсуждение.** В чате проекта пользователь рассказывает агенту, что хочет построить, прикладывает файлы. Агент задаёт вопросы и по ходу обсуждения создаёт бриф, архитектуру и ADR.
   - Если документация уже есть (в репозитории или где угодно ещё, в любом формате), её можно **импортировать** — см. «Импорт документации» ниже.
   - Для существующего проекта всё это необязательно. Можно сразу сказать «сделай фичу» или «доработай» — агент изучит код и предложит спецификацию или задачу.
3. **Планирование.** Для новой функциональности агент сначала пишет спецификацию, после её принятия предлагает этапы и задачи с зависимостями. Мелкая доработка или исправление — сразу задача, без спецификации и без этапа. Пользователь принимает, правит или отклоняет предложения.
4. **Выполнение.** Пользователь выбирает задачу, агента и модель, запускает. Задачи без взаимных зависимостей можно запускать параллельно.
5. **Наблюдение.** Внутри задачи пользователь видит живой вывод агента, отвечает на его вопросы, выдаёт разрешения, может остановить.
6. **Слияние.** Когда агент закончил, пользователь пишет в чате задачи — «доработай …» или «вливай». Во втором случае агент запрашивает слияние, в ленте появляется карточка подтверждения, пользователь подтверждает: Skaro вливает ветку задачи в основную, задача становится «Готово», зависящие от неё задачи разблокируются.
7. **Развитие.** Новые идеи и фичи — снова через чат проекта: агент пишет или обновляет спецификацию, предлагает задачи, при необходимости обновляет архитектуру и создаёт ADR. Задача, которая меняет поведение функции, предлагает правку её спецификации.

## Импорт документации

У существующего проекта обычно уже есть документация — в репозитории, в соседней папке, в выгрузке из Confluence или Notion, в docx и pdf. Skaro не работает с ней напрямую и не требует её перестраивать: агент один раз переносит её в формат Skaro, пользователь подтверждает.

1. **Источник.** «Импортировать документацию» → папка, файлы или архив. Где угодно на диске, в любом формате. Ссылки на веб-страницы не поддерживаются: страницу выгружают в файл.
2. **Копия.** Skaro копирует источник в данные приложения и переводит всё, что может, в текст. Источник не меняется.
3. **Перенос.** Отдельный чат «Импорт документации»: агент читает копию и код проекта, раскладывает содержимое по типам Skaro — бриф, архитектура с правилами, ADR, спецификации, свободные документы, этапы и задачи из бэклога. Сделанное задачами не становится. Если источники противоречат друг другу или коду, агент спрашивает.
4. **Подтверждение.** Одна карточка «Импорт готов» → экран проверки: всё, что получилось, по разделам, с галочками, источниками и просмотром; отдельно — что не перенесено и почему. «Импортировать выбранное» записывает выбранное в `.skaro/` одним действием.

Ничего не теряется: то, что не легло ни в один тип, становится свободным документом. Повторный импорт в проект с документами предлагает правки существующих, а не дубли.

## Жизненный цикл задачи

```
Не начата ──► В работе ⇄ Нужен ответ ──► На ревью ──► Готово
                 │        (все критерии       │ «Влить»
                 │         отмечены)          │
                 ▼                            │
               Ошибка ◄───────────────────────┘ (снята галочка → снова в работе)
```

- **На ревью** — все критерии приёмки отмечены (отчётом агента `submit_result` или пользователем), в ленте задачи ждёт карточка слияния. Остаётся одно действие — «Влить». Отдельного шага и экрана ревью нет. С включённым в общих настройках автоматическим слиянием задача минует «На ревью» и сразу становится «Готово»; агент сообщает о слиянии в ответе. Если задача работала прямо в основной папке, вливать нечего, и она сразу становится «Готово».
- **Заблокирована** — не отдельный статус, а признак: у задачи «Не начата» есть незавершённые зависимости. Такую задачу нельзя запустить.
- **Нужен ответ** — агент ждёт пользователя: вопрос, разрешение, или агент закончил ответ, а критерии приёмки отмечены не все.
- **Ошибка** — запуск завершился неудачно или был остановлен. Можно перезапустить.

## Что входит в первую версию (MVP)

- Главный экран со списком проектов и их статусом.
- Проекты во вкладках.
- Создание проекта (новая папка или существующий код).
- Чат проекта с агентом: создание брифа, архитектуры, ADR, спецификаций, этапов и задач.
- Импорт документации пользователя в формат Skaro (папка, файлы, архив).
- Спецификации: просмотр, статусы, связь с задачами.
- Документы: просмотр и редактирование.
- План (этапы + задачи + зависимости).
- Задачи: доска и список.
- Экран задачи: описание, лента агента, запуск, слияние.
- Параллельный запуск с ограничением числа слотов.
- Адаптеры Claude Code и Codex.
- Настройки: агенты, параллельность, проекты, уведомления, внешний вид. Параметры проекта: агент по умолчанию, ветки и слияние.

## Skaro Cloud (будущее, платно)

Облачный слой для команд, не заменяющий локальное приложение:

- обзор проектов, задач и активных запусков всей команды;
- роли и доступы;
- бюджеты и лимиты на использование AI;
- история и аудит действий агентов;
- синхронизация задач между участниками.

Индивидуальное использование Skaro остаётся бесплатным и open-source (AGPL-3.0).

## Что уходит из v1

- CLI (`skaro init`, `skaro ui` и т.д.) и web-дашборд на FastAPI.
- BYOK-адаптеры к 9 LLM-провайдерам, собственная сборка контекста (AST-индекс, отбор файлов).
- Фазы constitution / clarify / plan / implement / tests, генерация кода по этапам, AI_NOTES.
- Конституция, отдельный документ devplan.
- Фичи с фазами. Сама идея возвращается спецификацией (D-30) — документом без обязательных фаз.
- Экран Git как отдельный раздел (git-операции встроены в слияние задачи).
- Skills и пресеты стеков (гибкость теперь — в инструкциях проекта и настройках агента).
