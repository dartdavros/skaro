# BA-3: инструменты, права и процессы

Дата: 31.10.2026. Реализован внутренний слой инструментов; команды поддержаны
на Windows. Модельного loop, API-коннекторов и продуктового UI ещё нет.
Основание: [план](builtin-agent-plan.md), [ADR-0047](adr/0047-builtin-agent.md),
[ядро BA-2](builtin-agent-runtime.md).

## Реальные инструменты

Реализация: `packages/agent-runtime/src/tools/`. Единый каталог строится из
Zod-схем; неизвестное имя и лишние/неверные аргументы отклоняются.
Транспорт `invokeTool` проходит через адаптер и штатный native worker;
контроллеры задач и renderer новых ветвей по модели/провайдеру не получили.

| Инструмент | Фактическое поведение |
| --- | --- |
| find_files | Отсортированный обход разрешённого каталога, вложенные .gitignore, фильтр подстроки и страницы |
| search_text | Буквальный поиск с настройкой регистра, номера строк, страницы, явные пропуски binary/слишком больших файлов |
| read_file | Диапазон строк, hash полных байтов, encoding, продолжение длинной строки через column |
| apply_patch | create/update/delete, обязательный hash существующего файла, точные однозначные before/after hunks |
| exec_command | Настоящая команда в указанном shell/cwd, timeout и возврат управляемого processId |
| write_stdin | Ввод/EOF в принадлежащий сессии процесс, ожидание и чтение страницы вывода |
| stop_process | Остановка собственного процесса с проверкой OS identity и подтверждением завершения |
| ask_user | Сохраняемый вопрос через существующий Interaction; результат появляется после настоящего respond |
| update_plan | Сохраняемое plan.updated, уникальные IDs и не более одного активного шага |
| view_image | Реальный scoped-файл и ссылка с MIME/hash; обязательна проверенная image capability точного маршрута |

Независимые файловые чтения могут исполняться одновременно. Записи и
процессные команды проходят общую очередь доступа, не обгоняя ожидающего
писателя. Callback отзыва допуска проверяется до эффекта; interrupt/close
не ждут входа в обычную очередь команды, чтобы отменить долгую операцию.

## Файловая область

Host задаёт cwd, дополнительные readDirs, readOnly и приватный artifactDir.
Пути проверяются до доступа: граница разрешённых корней, реальные родители,
отсутствие traversal, symlink/junction, Windows device/normalized aliases и ADS.
Git metadata недоступна через файловые инструменты; запись `.skaro` остаётся
обязанностью существующих host handlers. Файлы первичного журнала/индекса
и каталог output artifacts также исключены из обычного файлового доступа.
readOnly не отменяется выбором режима full.

Чтение ограничено обычными файлами до 2 000 000 байт. Binary и невалидный UTF
дают явный отказ. Поддержаны UTF-8/UTF-16LE с BOM; patch сохраняет encoding
и существующие line endings. Контекст замены должен встречаться ровно один раз.
Hard-linked файлы не изменяются. Перед заменой повторно сверяются hash,
inode и mtime; новый файл пишется через exclusive create, update — через
fsync временного файла и atomic rename. Отсутствующий родитель создаваемого
файла автоматически не создаётся.

Это проверки приложения, не OS sandbox и не межпроцессная filesystem CAS:
сторонний редактор не обязан соблюдать внутреннюю очередь. Последняя проверка
предшествует rename/unlink; гонка внешней замены пути целиком не устраняется
одним Node API. При обнаруженном расхождении владелец не перезаписывается.
Ошибка после начатого создания, когда возможен частичный файл, сохраняется
как неизвестный исход и не превращается в безопасный автоматический повтор.

Обход ограничен 30 000 файлов и глубиной 40; scanLimited сообщает ограничение.
Текст выдаётся страницами до 32 768 символов, длинная строка имеет column cursor.
Search preview отмечает усечение; полный текст читается через read_file.
Пагинация описывает текущую файловую систему, не неподвижный снимок проекта.

## D-28 и подтверждения

У встроенного runtime сейчас **нет проверенного filesystem/network sandbox
backend**. `builtinSandboxStatus` возвращает verified:false/backend:unavailable.
Ни worker, ни worktree, ни Job Object не выдаются за такую песочницу.

| Режим | Файловые записи в cwd | Команды и ввод в shell |
| --- | --- | --- |
| ask | Точное подтверждение allow_once | Точное подтверждение allow_once |
| auto | Разрешены в разрешённой файловой области | Подтверждаются из-за отсутствия sandbox |
| full | Разрешены в файловой области | Выполняются по предоставленному владельцем full-допуску |

Чтения и остановка собственного процесса не требуют нового подтверждения.
Approval связан с устойчивым call ID и hash точных аргументов; разрешение
одной команды не переносится на другую. `allow_session` не предлагается
и не принимается вместо `allow_once`. Отказ, interrupt и закрытие не дают
позднего исполнения после ответа на уже отменённое ожидание.

Подтверждённая shell-команда без OS sandbox может обращаться за пределами cwd:
это ограничение явно проверяется D-28 probe в собственном каталоге теста.
Внутренняя классификация команды как «чтение» для обхода approval не применяется.
Неподтверждённая команда не запускает рабочий процесс.

## Windows Job Object и вывод

`agent-command-worker.js` входит в штатную сборку. Windows supervisor создаёт
Job Object с KILL_ON_JOB_CLOSE без разрешения breakaway и включает себя в job
до запуска command worker. До передачи команды runtime сохраняет PID/birth
supervisor в первичном журнале. Shell и обычные потомки наследуют job;
завершение владельца job закрывает его handle и завершает эти процессы.
Основание: [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

Job Object отвечает за время жизни наследуемых процессов, не ограничивает
файловую систему/сеть и не считается security sandbox. Нестандартные внешние
службы/брокеры запуска процессов этой реализацией не изолируются.
Если создание/назначение job невозможно, команда отклоняется; подмены
обычным неподконтрольным spawn нет. На других ОС managed command backend
пока явно не реализован; успешная эмуляция не используется.

Общие правила shell invocation вынесены из core в runtime/shell и
реэкспортируются прежним core API. PowerShell получает EncodedCommand,
UTF-8 и сохранение ненулевого exit code; cmd запускается штатным shell
механизмом Node. Окружение runtime/command worker/shell строится из общего
системного allowlist. API credentials и внутренние SKARO_COMMAND_* параметры
не передаются shell-команде.

stdout/stderr сохраняются в приватный файл, с backpressure. Модель получает
страницы до 16 KiB с byte cursor; UTF-8 code points не разрываются между
страницами. Невалидный UTF-8 отмечается, исходные bytes остаются в artifact.
Лимит дискового вывода — 64 MiB; превышение останавливает процесс с ошибкой,
а не объявляет усечённый вывод полным успешным результатом.
Timeout, stdin/EOF, фоновое исполнение, stop и exit code представлены явно.
Неиспользованный таймер ожидания отменяется, когда процесс завершился раньше.

## Журнал и восстановление

Первичный журнал расширен tool-request, effect и process facts; его schema
повышена с 1 до **2**. Host/events/projector остаются версии 1; публичный
release manifest остаётся v1. Старый runtime journal schema:1 отклоняется
с явной несовместимостью; автоматическая миграция не реализована.

Перед действием сохраняется intent, после — результат. Журнал сам сериализует
записи даже при параллельных чтениях. Call ID/hash проверяются на уровне
всей сессии и инструмента. Потеря подтверждения не порождает повтор эффекта.
Вопрос/approval и ответ сохраняются отдельно; доставка не заменяет ответ.

После потери runtime ранее работавший process root проверяется и останавливается;
его исход отмечается interrupted/unknown. Сохранённый вывод остаётся читаемым
через processId, stdin прежнего процесса не восстанавливается. Неизвестные
эффекты блокируют новые изменяющие действия; разрешены наблюдение и вопросы.
Остановленная сессия требует явного нового ввода владельца перед продолжением.
Состояние приёмки задач и самостоятельная очередь здесь не создаются.

## Границы приёмки

Команды и process tree проверяются на Windows настоящими процессами, а не
fake backend. Сценарии и результаты — в [плане](builtin-agent-plan.md).
Инструменты не используют модельные API и пока не встроены в агентный loop.
Положительная проверка view_image с настоящим проверенным маршрутом,
Linux/macOS command backend, OS security sandbox и продуктовый UI остаются
незакрытыми. Новых экранов, состояний или иконок в UI не добавлено.
