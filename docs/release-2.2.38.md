# Skaro 2.2.38

Выпуск исправляет вопросы, отмену карточек, диагностику блокеров и вставку
изображений. Версии закреплённых агентов, SDK и адаптеров не меняются.

## Изменения

- Любой ожидающий решения запрос включает существующий синий индикатор,
  даже когда модель продолжает работать.
- Для неоднозначного блокера координатор назначает диагностику модели.
  Карточка содержит конкретные варианты действий с последствиями вместо
  `other; other` и пустого поля «Укажите решение».
- Архиагент выполняет разрешённое восстановление через штатные инструменты.
  Продолжение допускается после фактической проверки условия; Stop, отказ
  и отсутствие прав сохраняют силу.
- Ответ через composer отменяет прежние видимые вопросы, включая защищённую
  форму с несколькими полями и нативный вопрос агента. Отмена сохраняется
  при восстановлении и повторном чтении истории. Добавлен `cancel_question`.
- Подтверждение принятого ответа сохраняется атомарно и переживает очистку
  mailbox. Ошибка проекции не создаёт ложный `decision_reply_uncertain`.
  Старый неизвестный исход не блокирует независимые новые команды.
- Изображение из системного буфера получает миниатюру также для Windows bitmap
  и файла из Проводника. Обычный текст, удаление и защита от дубликатов сохранены.
- Во время настоящего сжатия контекста отображается «Сжимает контекст»
  с утверждённой анимированной иконкой. Её геометрия, цвет и анимация сохранены.
- Внутренние диагностические команды не отображаются как сообщения владельца.

## Проверки

Локально прошли production build, lint изменённых файлов, TypeScript/Svelte
без ошибок и предупреждений, 57 адресных тестов в 20 файлах и проверка размеров
модулей. Приёмка выполнялась в штатном Skaro на зарегистрированном Cat-pilot,
без mock API и подмены backend.

Живые сценарии проверили защищённую форму, отмену через composer и явно,
нативный ответ и нативную отмену, восстановление истории и три настоящих
источника изображения в Windows clipboard. Модель автоматически диагностировала
остановленный Compose, предложила варианты, после выбора запустила сервис,
подтвердила HTTP 200 и закрытие инцидента; продолжение было доставлено.
Хеши продуктовых файлов Cat-pilot до и после совпали. Приёмочная задача
архивирована, собственный временный профиль и worktree удалены.

Один прогон сохранил отдельное завершение процесса Codex и не был засчитан;
следующий полный цикл прошёл. QA Electron зависал при закрытии, поэтому
завершались только собственные проверочные процессы. Нормальное завершение
приложения этим результатом не подтверждается.

Полный CI и шесть native установщиков выпускаются штатными workflows
с соблюдением [контракта публикации](updates.md). Подробности причины
зависшей карточки: [диагностика и восстановление](incident-model-recovery.md).

Владелец явно разрешил полный штатный CI/release suite с существующими fixtures
и HTTP test servers и переиспользование принятых canary/model-проверок
неизменённых pins (`agents_verified`). Новая проверка pins не заявляется.
