# Подготовка выпуска встроенного агента

Полное включение встроенного агента и default запрещено до приёмки BA-1–BA-9.
По новому поручению владельца выпускается 2.2.14 с бейджем «В разработке»,
неактивными полями и закрытыми продуктовыми task/chat hosts. Этот выпуск
приложения не является приёмкой или выпуском встроенного агента как готовой функции.
Владелец подтвердил этот порядок 03.11.2026. Версия и tag пока не назначены;
настоящие release assets не создавались и не публиковались этим документом.

## Текст для release notes после приёмки

Встроенный Skaro использует сохранённые BYOK Connection/Route в задачах и
чатах, общий lifecycle, scope и запросы разрешений. Реальные квитанции дают
учёт токенов и стоимости; лимит сессии необязателен. Повторяющиеся tool calls
без прогресса останавливаются с сохранением состояния при восстановлении.
Прямые каталоги API сохраняют неизвестные метаданные как unknown.

Фактические поддержанные платформы, модели и ограничения нужно указать по
результатам приёмки, а не по наличию коннектора или компиляции кода.

## Оставшиеся release gates

- Cat-pilot: T-006 до fresh checks/C4/assessment/submit, замечание и повторная
  сдача, T-008, worktree/environment handoff, capture/merge.
- Положительные route/provider и owner approval/evidence сценарии.
- Штатная browser-проверка product UI, сохранность owner settings/history.
- Реальные Windows/macOS/Linux x64/arm64 и packaged payload; недоступная
  платформа не заменяется успешной Windows-проверкой.
- Обновление предыдущего комплекта, сохранность managed pins и старых историй.
- Принятые ограничения D-28, неизвестные данные usage и поддержанные inputs.

`BUILTIN_DEFAULT_RELEASED=false` остаётся закрытым gate в
`packages/agents/src/builtin-default.ts`. После приёмки отдельное включение
меняет только выбор для новых настроек. Сохранённый выбор владельца не
переписывается; текущий порядок managed агентов и release manifest сохраняется.

## Порядок публикации

Использовать [действующий контракт выпуска](updates.md), его штатные scripts
build/package/manifest/publish и реальный согласованный bundleVersion.
`publish-release.mjs` формирует обязательную таблицу `System | x64 | arm64`
со строками Windows/macOS/Linux и шестью ссылками Download на установщики
именно этого релиза. Не подставлять вымышленные URL заранее. После публикации
проверить таблицу, соответствие шести assets и доступность каждого файла.
