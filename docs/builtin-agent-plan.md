# Встроенный агент: план реализации и приёмки

Дата: 31.10.2026. Статус: BA-1 — контракты; BA-2 — ядро lifecycle;
BA-3 — инструменты и команды Windows, с ограничениями D-28. Полная приёмка
этих этапов ещё не закрыта. BA-4 начат: vault и четыре коннектора в коде,
OpenRouter проверен живыми cases; прямые API отложены владельцем. BA-5 принят
в текущем поддерживаемом контуре Windows: scoped context/skills, длительная
сессия после compact/restart, границы маршрутов, HTTP/internal MCP и настоящий
task browser/media. [Итоговая таблица](builtin-agent-ba5-acceptance.md) фиксирует
доказательства и платформенные ограничения.
BA-6 начат: [run_check и привязка доказательств к входам](builtin-agent-checks.md);
добавлены read-only criteria/completion/C4 projection и evidence preflight
(01.11.2026), host dependency measurements и task-bound command plans.
Живой read-only model-plan на Cat-pilot через включённый VPN принят;
полный цикл исправления и сдача активной задачи ещё не подтверждены.
Полная приёмка открыта. Подготовлен [native inspection bridge](builtin-agent-native-verification.md)
и [native host operations](builtin-agent-native-operations.md) для BA-7;
проверен [общий отзыв native-сессии](builtin-agent-native-lifetime.md).
Продуктовые задачи/чаты и scheduler не подключены. BA-8 начат; в BA-9
предварительно проверен локальный Windows x64 payload, полная приёмка открыта.
Добавлен [native model host](builtin-agent-native-model.md): concurrent negative
preflight и живой native model-plan Cat-pilot приняты; пять запросов через Xray,
реальные tools/streaming/budget/dedup. Это не выполнение или сдача активной задачи.
Принят [durable process admission](builtin-agent-native-admissions.md): поколения,
OS ownership, отзыв и подтверждённый выход; task/chat binding остаётся следующим шагом.
Добавлена [привязка к task-run](builtin-agent-task-admission.md): настоящие
identity/session/handoff gates; положительная приёмка активной builtin-задачи открыта.
Приняты [канонический model turn и поток сообщений](builtin-agent-model-timeline.md):
настоящие streaming deltas, один terminal и совпадение live/replay на Cat-pilot.
Принят [bootstrap каталога MCP](builtin-agent-operation-bootstrap.md) до spawn:
метаданные из штатного реестра, выполнение только после durable process admission.
Принят [обычный owner input](builtin-agent-owner-input.md) до host preparation:
send → durable input → прежний model loop, без повторной доставки после restart.
Добавлен [active steering boundary](builtin-agent-owner-steering.md): два input
одного хода на native Cat-pilot; provider-приёмка steering ещё открыта.
Добавлено [backend-хранилище Connection/Route](builtin-agent-model-configuration.md):
атомарные ревизии и общие connector validators, без включения UI или model admission.
Добавлен [configured model host](builtin-agent-configured-model-host.md): точные
route/credential reference и отзыв устаревшего lease. Положительный configured
read-only model-plan принят 02.11.2026; активная task/chat интеграция открыта.
Исправлена [граница проверочного запуска](builtin-agent-project-scope.md): Cat-pilot
выбирается до startup/recovery/watchers и Docker cleanup, не только внутри сценария.
Добавлены [настройки подключений и маршрутов](builtin-agent-model-settings.md):
main IPC, защищённое хранение и формы существующего раздела «Агенты».
Полная приёмка BA-8 и включение встроенного агента остаются открытыми.
Добавлен [общий credential authority](builtin-agent-configured-credentials.md)
для settings и configured host; подготовка до spawn, два настоящих поколения
процессов, отказы до чтения ключа и отзыв приняты на Cat-pilot, model requests 0.
Добавлен [настоящий каталог OpenRouter](builtin-agent-model-catalog.md):
GET через VPN, schema/cache/dedup и catalog-only capabilities проверены;
picker/loading/refresh и пустой выбор проверены в штатном Electron на Cat-pilot.
Подготовлена [сборка configured model host](builtin-agent-configured-host.md):
четыре настоящих коннектора, явный transport и обязательные request gates;
native turn/RPC и отказ перед POST приняты на Cat-pilot, live/replay совпали,
owned process вышел. Это не положительная provider-приёмка активной задачи.
Через тот же factory приняты обычные durable send/steer одного хода, dedup,
отказ конфликтующему input ID и automatic native close; новых POST нет.
Configured session возобновлена во втором настоящем runtime/admission generation:
старые send/steer IDs не повторили подготовку или intent, replay совпал.
Предварительно проверен [локальный Windows x64 payload](builtin-agent-package-verification.md):
настоящий EXE/ASAR, byte-for-byte worker entries и packaged settings/catalog.
Это не релиз и не закрытие BA-9 остальных платформ/модельной задачи.
Configured host требует отдельную проверку актуальных model metadata до
подготовки и перед reservation/POST; [каталоговый guard](builtin-agent-model-catalog.md#проверка-маршрута-на-границе-host)
не превращает advertised capabilities в verified readiness.
Добавлена [подготовка owner input из primary context](builtin-agent-context-input.md):
настоящий compact и свежий ввод во втором native-поколении сохраняют epoch,
точные owner statements и history refs; reservation/POST остаются запрещены.
Приняты [каталоговые уровни усилия](builtin-agent-model-effort.md) в прежней форме
Route: точные metadata, JSON sync и явный отказ несовместимому уровню проверены
на Cat-pilot; provider reasoning/расход и полная BA-8 ещё не приняты.
Принят [живой configured plan](builtin-agent-configured-plan.md) после отдельного
согласования: пять POST, три настоящих tools, ordinary send, streaming/live-replay
и restart с нулём новых POST. Общий ledger 85 intents / $0.39324124 расходов
и удержаний, пять дополнительных запросов использованы. Выполнение/сдача задачи
и полная BA-7 остаются открытыми.
Добавлен [read-only учёт reported usage](builtin-agent-model-usage.md): квитанции
из primary journal, точные decimal суммы и явный unknown; бюджетные удержания
учитываются отдельно. UI расхода и полная приёмка ещё открыты.
Основание: [ADR-0047](adr/0047-builtin-agent.md), решение владельца об основном
агенте Skaro, BYOK и самостоятельном исправлении ошибок до проверенной сдачи.
Текущее продолжение — BA-6/BA-7 и настройки BA-8; встроенный агент пока не
включён в task/chat picker и не становится выбором по умолчанию.
BA-* — локальные ID плана, не созданные задачи Skaro.

## Объём и зависимости

Первая очередь: встроенный агент, прямые OpenAI/Anthropic/DeepSeek, OpenRouter,
один исполнитель, файловые/процессные инструменты, вопросы/права, resume,
compact/rewind, browser/MCP/skills и самостоятельные проверки с исправлениями.
Другие API-сервисы расширяют коннекторы и конфигурацию, не общий loop.
Claude Code/Codex остаются альтернативами.

| Этап                          | Зависимости                     | Самостоятельный результат                            |
| ----------------------------- | ------------------------------- | ---------------------------------------------------- |

| BA-5 Контекст и расширения    | BA-3, BA-4                      | Компактный контекст, compact, browser/MCP/skills     |
| BA-6 Проверка и исправления   | BA-3, BA-4, BA-5                | Доказательства и цикл до проверенной сдачи           |

Design work для BA-8 можно подготовить раньше; код зависимого UI начинается
после принятия дизайна. Последовательность этапов не разрешает субагентов
или параллельную запись исполнителей в один checkout.

Решение владельца от 01.11.2026 для BA-8: «Используй существующие UI елементы
системы и визуальный язык». Согласовано переиспользование текущих settings
surfaces/components/tokens и состояний. Отдельный новый визуальный язык не
требуется; исходный baseline изучается до правок, штатная browser-проверка
обязательна. Настройки BA-8 реализуются по этому решению; закрытие полного
этапа требует отдельной проверки оставшихся моделей/capabilities/feed/расхода.

| packages/core/src/agents/                  | Сохранение установки внешних агентов         |

| packages/timeline/src/replay.ts            | Восстановление ленты из первичной истории    |

Предлагаются packages/agent-runtime и packages/adapter-skaro. Runtime делится
на session/loop, journal/recovery, context, tools/policy, providers и verification;
это области ответственности, не требование создать много пакетов заранее.
Публичные DTO и host-порты фиксируются в BA-1. SDK/Node не попадают в renderer.
Не создаются второй completion service, самостоятельная очередь задач или
альтернативные handlers продуктовых операций.

## BA-1. Контракты, регистрация и поставка

- Разделить bundled и managed-npm дистрибутив в общем контракте. Готовность
  runtime отделить от наличия подходящего настроенного API-подключения.
- Ввести Connection, Model, Route и версионированные API-профили/capabilities.
  ID модели принадлежит подключению; производитель и upstream — разные поля.
- Определить host-порты: scoped операции Skaro, credentials, события,
  процессный допуск, окружение и проверка состояния приёмки.
- Определить системное защищённое хранение ключей и ротацию; секреты не входят
  в DTO каталога, env команд, настройки Git, журнал и диагностический вывод.
- Зафиксировать versioning runtime, событий, проектора и SDK. Сохранить
  release manifest v1; необходимость новой схемы вынести в отдельное решение.

Приёмка: внешний агент проходит прежний путь установки/входа; bundled агент
не требует фиктивной загрузки или подписки. Неизвестные IDs отвергаются.
Два подключения к одному сервису и одна модель через direct/шлюз различимы.
Нет ветвей по ID модели/провайдера в контроллерах задач или UI-каталоге.

## BA-2. Изолированный runtime, журнал и lifecycle

- Реализовать отдельный процесс с записью PID/identity до допуска действий,
  отменой startup, ограниченным shutdown и подтверждением выхода потомков.
- Реализовать send/steer/respond, смену модели/прав, interrupt/close; вопросы
  и решения имеют устойчивые IDs и сохраняемые состояния.
- Создать единый журнал с версией и checkpoints; существующая лента строится
  проектором. Native continuation хранится как расширение первичной истории.
- Восстановить точную сессию после перезапуска; неизвестный исход операции
  не превращается в автоматический повтор. Явная остановка сохраняется.
- Определить conversation rewind и границы compact. История остаётся доступной;
  откат файлов использует существующий механизм с защитой чужих изменений.

Приёмка: отмена во время startup, запроса, инструмента и вопроса не допускает
позднего действия. Два одновременных входа не создают два runtime одной сессии.
Повтор доставки не дублирует ход/решение. Сбой после эффекта до записи результата
восстанавливается как неизвестный исход. Replay совпадает с живой лентой.

## BA-3. Инструменты, процессы и sandbox

- Реализовать find_files/search_text/read_file и apply_patch с ограничениями
  области, проверкой исходного содержимого, кодировок и чужих изменений.
- Реализовать exec_command/write_stdin/stop_process: shell/cwd, вывод,
  timeout, stdin, фоновые процессы, владение и подтверждение остановки.
- Добавить общий реестр схем, политик, отмены, эффектов и результатов;
  независимые чтения параллельны, конфликтующие записи упорядочены.
- Сохранить режимы прав и D-28. Отдельно проверить OS sandbox backend;
  worker, worktree, MCP scope или эвристика shell не заменяют ограничение доступа.
- Реализовать ask_user/update_plan/view_image; неподдерживаемые изображения
  дают явную несовместимость маршрута. Имена новых UI-элементов не придумывать.

Приёмка: реальные чтение/поиск/patch, конкурентное изменение файла, длинный вывод,
stdin, timeout и дерево процессов проверены. Команда не получает credential
модели. Выход за пределы прав и работа после отзыва допуска не разрешаются.
Отсутствующая sandbox-гарантия явно учитывается по действующему D-28.

## BA-4. OpenAI, Anthropic, DeepSeek и OpenRouter

- Реализовать коннекторы по профилям ADR: OpenAI Responses, Anthropic Messages,
  DeepSeek Chat Completions, OpenRouter Chat Completions. Общие transport-части
  переиспользуются, native semantics и ошибки остаются в коннекторе.
- Получать каталог/доступность поддерживаемым сервисом способом. Каталог не
  гарантирует доступ модели; исчезновение записи не подменяет сохранённый ID.
- Сохранять модель/маршрут и продолжение: OpenAI items, Anthropic blocks,
  DeepSeek reasoning_content, OpenRouter reasoning_details. Не терять порядок
  и native IDs в streaming и tool-call/result парах.
- Для OpenRouter применить согласованную upstream/fallback policy, обязательную
  поддержку параметров, ограничения обработки данных и нормализацию usage.
  Реальный upstream сохраняется, если возвращён; неизвестное не выдумывается.
- Дополнительный совместимый endpoint настраивается через Connection и
  проверенный профиль; новый несовместимый API добавляет коннектор.
- Разделить безопасный сетевой retry с backoff/отменой и новый агентный шаг.
  Не повторять выполненные инструменты при retry; streaming обрыв не выдавать
  за успешное завершение. Учёт usage/cost не дублируется по повторной доставке.

Приёмка для каждого подключения: настоящая цепочка минимум двух вызовов
инструментов, streaming, продолжение, ошибки инструмента, отмена и восстановление.
Для OpenRouter проверить доступные маршруты разных производителей моделей,
отказ несовместимого параметра и соблюдение настроенного fallback. Не требовать
от отсутствующей в аккаунте модели фиктивного успешного ответа.

## BA-5. Контекст, compact, browser/MCP/skills

- Собирать инструкции по области и актуальные task/ADR/C4/решения с ревизиями.
  Большие результаты, документы и историю читать частями по ссылкам.
- Разделить достоверные решения и рабочие заметки; данные tools/web/repository
  не становятся разрешениями. Обновлять устаревший контекст при изменениях.
- Реализовать compact с сохранением точных ограничений и открытых решений,
  полного журнала и ссылок на доказательства; native state не редактировать
  как текст. Native compaction опциональна по реальной поддержке маршрута.
- Подключить существующий Playwright MCP, stdio/HTTP MCP, skills и продуктовые
  операции с прежними scopes/подтверждениями и ограничением каталога инструментов.
- Проверить смену маршрута на безопасной границе: общие факты сохраняются,
  несовместимые закрытые continuation-данные не отправляются новому провайдеру.

Приёмка: длинная реальная сессия продолжается после compact и перезапуска,
решения/вопросы не теряются. Browser работает со штатным окружением задачи.
Недоступный MCP/маршрут даёт наблюдаемую ошибку. Нет дополнительного канала
отправки журналов или обхода подтверждений при внутренних вызовах Skaro.

## BA-6. Самостоятельная проверка, исправления и доказательства

- Модель строит план проверок по правилам проекта, критериям, CI и изменениям;
  сопоставляет проверки с требованиями. Новый тест добавляется ради поведения.
- run_check использует общий executor, но сохраняет структурированные факты:
  IDs, команда/сценарий, cwd, inputs, окружение/инструменты, вывод и артефакты.
  Browser-наблюдения также имеют происхождение и связь с критериями.
- Привязать доказательства к tracked/dirty/untracked inputs и применимым
  ревизиям. После изменения затронутые результаты устаревают; неизвестная
  зависимость не считается безопасной. HEAD сам по себе недостаточен.
- Реализовать цикл диагностика → причина → исправление → повтор упавшего и
  затронутого → проверка критериев/diff. Сохранять и неудачные попытки.
- Различать дефект реализации, ошибку команды, инфраструктуру, нестабильность
  и несвязанный дефект. Не расширять задачу и не ослаблять тесты ради зелёного.
- Расширить общую приёмку ссылками на доказательства и причинами отказа;
  встроенный агент продолжает работу через существующий completion process.
  Совместимость submit_result внешних агентов проверяется явно.

Приёмка: значимая ошибка обнаружена реальной проверкой, исправлена и проверена
повторно. Старый успех не принимается после изменения входов. Ложная ссылка
или текст «проверено» не создают доказательство. Невыполненные критерии,
устаревший необходимый C4-review и открытое решение не обходятся сдачей.
Недостаток покрытия не объявляется математически доказанным одной машинной
проверкой списка команд; остаётся инженерная оценка критериев и рисков.

## BA-7. Задачи, чаты, очередь и альтернативные агенты

- Включить runtime в существующие task/chat/native lifecycle, process ownership,
  очередь, окружения и общий механизм взаимодействий.
- Сохранить самостоятельное продолжение незавершённой задачи, причины ожидания,
  бюджет/отмену и ограничитель отсутствия прогресса. Не создавать второй scheduler.
- Интегрировать submit_result с существующими capture/C4/merge. D-45 не меняется:
  на слиянии только configured checks, без нового общего прогона результата.
- Проверить handoff встроенный ↔ Claude/Codex с сохранением worktree,
  окружения, истории, вопросов и истечением прежних разрешений.

Приёмка: задача доходит от постановки до проверенной сдачи и предусмотренного
слияния, замечание продолжает её. Перезапуск и смена агента не дублируют эффекты,
не теряют входы и не меняют сохранённый выбор/права других проектов.

## BA-8. Дизайн и UI интеграции

До правок получить утверждённый дизайн для имени/логотипа, Connection и ключей,
моделей/effort, routing/capabilities, ошибок, недоступности защищённого хранилища
и расхода. Не выдавать BYOK balance за окна подписки. Согласовать необходимые
состояния в существующих settings/picker/feed; новые экраны не подразумеваются.

Затем реализовать по baseline безопасный IPC, управление подключениями и
выбором. Чувствительные значения не возвращаются API чтения настроек;
область временного ввода/сохранения ключа проектируется отдельно.
Loading/error/ready сохраняют геометрию, используется общий spinner.

Приёмка: browser-проверка настоящего Electron с реальными подключениями,
моделями и задачей; визуальная сверка с утверждённым дизайном. Отсутствующий
дизайн блокирует зависимую UI-часть, не разрешает временный продуктовый интерфейс.

## BA-9. Проверка выпуска и переход к основному агенту

- Провести сквозную приёмку маршрутов, lifecycle, sandbox, автономного исправления,
  replay/handoff и сохранности данных на целевых Windows/macOS/Linux x64/arm64.
- Проверить обновление bundled runtime и старых историй; managed агенты и
  manifest/integrity не регрессируют. Недоступная целевая платформа остаётся
  незакрытым критерием, не подменяется успешной проверкой другой платформы.
- Сделать встроенного агента выбором по умолчанию для новых настроек после
  приёмки. Существующий выбор не переписывать и скрытый fallback не включать.
- Измерить принятые реальные задачи, исправления после ревью, время и стоимость.
  Сравнение разных моделей не доказывает преимущество одного harness.

Приёмка: опубликованы реальные результаты и ограничения. Переход не означает
готовность неподдержанного маршрута. Выпуск соблюдает docs/updates.md,
включая таблицу шести установщиков; сам план не разрешает публикацию релиза.

## Правила проверок и незакрытые решения

Для каждого изменения кода — сборка и только тесты значимого изменённого
поведения/затронутых сценариев. Исключения для документации и мелких UI-правок
сохраняются; полный suite только перед релизом или по прямому указанию.
Подключения проверяются настоящими API с доступными ключами и согласованными
бюджетами; запрет mock API/fixtures/seed/временных серверов сохраняется.
Для runtime/browser нужен штатный контур. Его отсутствие — честный blocker.

До соответствующих этапов определить: API/DTO и migration policy (BA-1),
OS sandbox и secure storage (BA-1/BA-3), доступные модели и routing/бюджеты
(BA-4), дизайн (BA-8). Секреты в репозитории не сохраняются. Субагенты, LSP,
автоматический выбор моделей, code orchestration и отдельный ревьюер отложены.
