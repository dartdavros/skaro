# План реализации Skaro v2

Что делаем: десктоп-приложение на Electron (Windows, macOS, Linux), TypeScript целиком — фоновая часть на Node, интерфейс на Svelte 5 (D-01, D-19). Как устроено — в [architecture.md](architecture.md) и [agent-output.md](agent-output.md). Интерфейс — [mockups/](mockups/).

Порядок выбран по риску: сначала проверяем самое хрупкое (работу с агентами), потом строим ядро и сквозной сценарий, потом остальные экраны.

---

## Этап 0. Репозиторий и инструменты

- Код v1 — в ветку `legacy/v1` и тег `v1-final` (D-07). В `main` остаются `docs/` и новый каркас.
- Структура монорепозитория (pnpm workspaces):

```
apps/desktop/          Electron: main, preload (мост IPC), renderer (Svelte 5)
packages/core/         домен: проекты, этапы, задачи, статусы, артефакты .skaro/
packages/timeline/     каноническая модель ленты, проекция из сырого потока
packages/adapter-claude/   адаптер Claude Code (Agent SDK)
packages/adapter-codex/    адаптер Codex (app-server, JSON-RPC)
packages/mcp-server/   MCP-сервер Skaro (предложения документов, ADR, этапов, задач)
packages/ui/           компоненты по «Инвентарю UI»
fixtures/golden/       записанные сессии агентов для контрактных тестов
```

- Инструменты: TypeScript strict, ESLint, Prettier, Vitest (модульные тесты), Playwright для Electron (сквозные), electron-builder.
- CI (GitHub Actions): линтер, проверка типов, тесты, golden-тесты адаптеров, сборка под три ОС.

**Готово, когда:** пустое окно Electron собирается и запускается на трёх ОС из CI, v1 сохранён в `legacy/v1`.

## Этап 1. Прототип адаптеров агентов

Без интерфейса — консольный стенд на Node, который запускает агента и печатает канонические события.

- **Claude Code:** Agent SDK с собственным бинарником. Проверить:
  - `canUseTool` — разрешения и `AskUserQuestion`;
  - Task-инструменты плана (включить явно);
  - `interrupt`, `streamInput`, `resume`, `rewindFiles`;
  - режим `plan` и одобрение `ExitPlanMode`;
  - `setPermissionMode`, изображения, субагенты.
- **Codex:** `codex app-server`. Проверить:
  - рукопожатие, `thread/start`, `turn/start` / `steer` / `interrupt`, `thread/revert`;
  - подтверждения команд и файлов, `requestUserInput`;
  - `turn/plan/updated`, изображения;
  - `account/login`.
- **Открытые вопросы, которые закрывает прототип:**
  - можно ли войти в Claude Code прямо из Skaro;
  - как ведёт себя песочница Claude на Windows;
  - как подключаются `~/.claude` и `~/.codex` (D-25);
  - как докачивать закреплённые бинарники (контрольные суммы, место хранения).
- **Записать golden-сессии** по сценариям из agent-output.md (П8): чтение, правка, падающая команда, фоновая команда, вопрос, разрешение, субагент, прерывание, ошибка авторизации, сжатие, изображение, «сначала план», откат.

**Нужно от тебя:** на машине для разработки войти в Claude Code и установить Codex и войти в него. Учётные данные вводишь ты.

**Готово, когда:** по каждому сценарию есть сырая запись и её канонический вывод. Выводы по открытым вопросам записаны в agent-output.md.

## Этап 2. Ядро

- **Артефакты `.skaro/`:**
  - чтение и запись Markdown с frontmatter (бриф, архитектура, ADR, этапы, задачи, документы);
  - слежение за ручными правками;
  - вычисляемые статусы («Заблокирована», прогресс этапа).
- **AppDb (SQLite):** проекты, открытые вкладки, настройки, оперативное состояние задач, индекс запусков и чатов, открытые взаимодействия.
- **GitService:**
  - worktree и ветка на задачу;
  - проверки перед слиянием (чистая рабочая копия, актуальность ветки, пробное слияние, изменения `.skaro/`);
  - squash или merge;
  - отмена слияния через `revert`.
- **RunQueue:** слоты параллельных запусков (по умолчанию 3), очередь, запуск только незаблокированных задач.
- **Установщик агентов:** докачка закреплённых версий с прогрессом и проверкой целостности.

**Готово, когда:** модульные тесты покрывают статусы, зависимости, очередь и все ветки слияния на тестовых репозиториях.

## Этап 3. Каноническая модель и адаптеры

- `packages/timeline`: типы из agent-output.md (раздел 3), сборка ленты из событий, пересборка из сырого JSONL с версией адаптера.
- Адаптеры Claude Code и Codex в полном объёме:
  - маппинг из разделов 4.1–4.3;
  - реестр инструментов;
  - толерантный разбор;
  - категории ошибок;
  - изображения в `attachments/`;
  - живая строка;
  - заполненность контекста.
- Взаимодействия туда и обратно: разрешения, вопросы, одобрение плана, формы и вход MCP.
- Самопроверка песочницы перед первым запуском и режим «Авто в пределах задачи» по её результату (D-28).
- Golden-тесты в CI.

**Готово, когда:** все golden-сессии обоих агентов дают ожидаемую ленту, а неизвестные события не роняют разбор.

## Этап 4. Оболочка и компоненты

- Окно без системной рамки, вкладки проектов в заголовке, восстановление вкладок, боковое меню проекта.
- Типизированный мост IPC (renderer без доступа к Node).
- Токены и компоненты из «Инвентаря UI»:
  - кнопки, переключатель, тумблер, ползунок усилия;
  - выпадающие списки, поля, чекбоксы, радио-карточки;
  - тултипы, баннеры, модалки, прогресс;
  - вкладки, карточки.
- Локализация ru/en.

**Готово, когда:** все элементы инвентаря собраны в Svelte и выглядят как в макете.

## Этап 5. Сквозной сценарий: задача с агентом

Экран «Задача» и лента по «Ленте агента»:
- все строки событий, группы, размышления, субагенты, изображения, форматирование, служебные строки;
- карточки вопроса, разрешения и плана;
- закреплённая зона над полем ввода: план и фоновые задачи;
- поле ввода: «/», «@», вложения, процент контекста, пилюли режима прав и «План», очередь сообщений;
- модалка агента;
- откат, повтор, редактирование;
- минимальный MCP-сервер Skaro с `merge_task` и карточка слияния.

Цикл: запуск в worktree → работа → «На ревью» → в чате задачи «доработай» или «вливай» → агент вызывает `merge_task` → карточка подтверждения в ленте → Skaro вливает → «Готово» → зависимые задачи разблокированы (D-27).

Сначала на Claude Code, затем тот же экран на Codex. Интерфейс при этом не меняется — это и есть проверка архитектуры.

**Готово, когда:** обе задачи проходят цикл до слияния, лента одинакова для обоих агентов, после перезапуска Skaro сессия восстанавливается.

## Этап 6. Чаты проекта и MCP-сервер Skaro

- Чаты проекта = сессии агента: список, архив, запрет смены агента в начатом чате.
- MCP-сервер Skaro: `get_project_context`, `write_doc`, `propose_adr`, `propose_milestones`, `propose_tasks`, `update_task`.
- Карточки предложений: документ с диффом, ADR, этап с задачами. Автоприменение документов, откат.
- Чат только читает код.

**Готово, когда:** из чата создаются бриф, архитектура, ADR, этапы и задачи, и всё это записывается в `.skaro/`.

## Этап 7. Остальные экраны

- **«Проекты»:** карточки, поиск и сортировка, создание и подключение проекта, проект не найден, баннер про агента.
- **«Обзор»:** требует внимания, сейчас работают, чек-лист старта, этапы, события.
- **«Документы»:** дерево, просмотр с Mermaid и оглавлением, редактор, статусы ADR, конфликт с диском.
- **«План»:** этапы, зависимости при наведении, перетаскивание, создание и правка этапа.
- **«Задачи»:** доска и список, фильтры, массовый запуск с очередью, перенос, архив, удаление, разблокировка.
- **«Параметры проекта»** и **«Настройки»:** агенты — загрузка, вход, модели, подключённые настройки пользователя; запуски, проекты, уведомления, внешний вид, о программе.

**Готово, когда:** все экраны из `mockups/` работают на реальных данных.

## Этап 8. Надёжность и выпуск

- Ночная канарейка на свежих версиях агентов, отчёт о различиях (agent-output.md, раздел 8).
- Диагностика: счётчик необработанных событий, экспорт сырых строк.
- Системные уведомления, блок Skaro в `AGENTS.md` / `CLAUDE.md`.
- Производительность: виртуализация длинной ленты, пачки дельт, большие диффы и выводы.
- Безопасность: изоляция renderer, санитизация HTML и Markdown, MCP-сервер только на localhost с токеном сессии.
- Установщики под три ОС, подпись и нотаризация, автообновление через GitHub Releases.
- README v2, выпуск бета-версии.
