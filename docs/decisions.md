# Журнал решений Skaro v2

Короткий реестр принятых решений по переходу на v2. Подробности — в [product.md](product.md), [architecture.md](architecture.md), [agent-output.md](agent-output.md).

Статусы: **принято** — согласовано с владельцем продукта; **предложено** — рабочая гипотеза, можно пересмотреть.

| # | Решение | Статус |
|---|---|---|
| D-01 | Skaro — десктоп-приложение на Electron (Windows, macOS, Linux). CLI и web-дашборд v1 не развиваются. | принято |
| D-02 | Skaro не пишет код сам и не содержит BYOK-адаптеров к LLM. Вся работа с моделями — через установленные у пользователя coding-агенты: Claude Code и Codex. | принято |
| D-03 | Агенты работают по подписке пользователя (его собственная авторизация в CLI). API-ключи не требуются. | принято |
| D-04 | Skaro — оркестратор и инструмент контроля: проекты, документация, этапы, задачи, запуск агентов, живой вывод и слияние. | принято |
| D-05 | Поддержка агентов — через единый интерфейс адаптера. Claude Code и Codex — в первой версии, остальные агенты добавляются адаптерами. | принято |
| D-06 | Целевой пользователь v2 — разработчик-одиночка. Skaro Cloud (команды, бюджеты, доступы) — позже, как платная часть. | принято |
| D-07 | Разработка продолжается в существующем репозитории `skarodev/skaro` (сохраняем звёзды). Код v1 сохраняется в ветке `legacy/v1` и теге `v1-final`. | принято |
| D-08 | Артефакты проекта: бриф, архитектура (включая правила и ограничения), ADR, этапы, задачи, свободные документы. Конституции нет — её роль берёт раздел «Правила и ограничения» архитектуры. | принято |
| D-09 | Фич как отдельной сущности нет. Новая функциональность обсуждается с агентом в чате и превращается в задачи. | принято |
| D-10 | Отдельного документа плана нет. План — вычисляемое представление: этапы + задачи + зависимости. | принято |
| D-11 | Фазы v1 (constitution → architecture → clarify → plan → implement → tests) упраздняются. Вместо них — жизненный цикл задачи: не начата → в работе → на ревью → готово. | принято |
| D-12 | Каждый запуск задачи по умолчанию идёт в отдельном git worktree и ветке. Это обязательно для параллельного выполнения. | принято |
| D-13 | Слияние выполняет Skaro, только после явного подтверждения пользователя и с проверками безопасности (см. architecture.md, раздел «Слияние»). | принято |
| D-14 | Чат с агентом есть на уровне проекта (планирование, документация, новые задачи) и на уровне задачи (обсуждение без изменения кода). | принято |
| D-15 | Автопилот (автоматический запуск всех готовых задач по графу) — не в первой версии. | принято |
| D-16 | Skaro поднимает собственный MCP-сервер, через который агенты читают и изменяют артефакты проекта (задачи, документы, ADR). Изменения задач агентом требуют подтверждения пользователя. | предложено |
| D-17 | Каталог `.skaro/` в репозитории меняет только Skaro (в основной рабочей копии). Изменения `.skaro/` внутри веток задач при слиянии отбрасываются. | предложено |
| D-18 | Логи запусков агентов хранятся в данных приложения, а не в репозитории. В файл задачи попадает только итог. | предложено |
| D-19 | Стек: TypeScript целиком (Electron main + Svelte 5 renderer). Без Python-сайдкара. UI-компоненты и промпты v1 переиспользуются выборочно. | предложено |
| D-20 | Вывод агентов проходит три слоя: транспорт → адаптер агента → каноническая модель ленты. Интерфейс не знает нативных форматов агентов (см. agent-output.md). | предложено |
| D-21 | Сырой поток агента — источник истины. Каноническая лента — пересобираемая проекция с версией адаптера. | предложено |
| D-22 | Изменённые файлы, diff и статус проверок Skaro вычисляет сам (git, CheckRunner), а не берёт из вывода агента. | предложено |
| D-23 | Claude Code подключается через Agent SDK с его собственным бинарником, Codex — через `codex app-server` (JSON-RPC v2). Версии обоих агентов закреплены релизом Skaro, бинарники докачиваются при первом использовании. | принято |
| D-24 | В ленте агента поддерживаются: откат к сообщению, повтор ответа, редактирование отправленного, режим «сначала план» с одобрением, смена режима прав на лету, вход в агента из Skaro. Смена агента в начатом чате запрещена (см. agent-output.md, раздел 7). | принято |
| D-25 | Пользовательские настройки агентов (`~/.claude`, `~/.codex`: хуки, MCP-серверы, навыки, глобальные инструкции) подключаются к запускам Skaro. | принято |
| D-26 | Закреплённые версии агентов обновляются раз в 2–4 недели и внепланово при выходе новой модели. Перед обновлением — ночная канарейка и golden-тесты адаптеров (см. agent-output.md, раздел 8). | предложено |
| D-27 | Отдельного ревью нет. Слияние подтверждается в чате задачи: пользователь пишет агенту, агент запрашивает слияние через инструмент Skaro `merge_task`, в ленте появляется карточка подтверждения, слияние выполняет Skaro (D-13). | принято |
