# Skaro 2.2.35

Выпуск по поручению владельца от 15.11.2026 объединяет уточнения навигации
и ленты, удаление искусственных ресурсных блокировок и исправления согласований.

- Активные задачи слева показывают ID вида `T016`. Правый мигающий индикатор
  работающей задачи заменён прежней иконкой активности размером 12px.
- Сводка изменённых файлов показывает первые три файла и раскрытие остальных.
- Остаток лимита показан белым круговым индикатором 20px. Подсказка содержит
  отдельные строки доступных окон; отсутствующее пятичасовое окно скрывается.
- CPU, RAM, диск, Docker pools, внутренние слоты и сохранённые квоты больше
  не запрещают выполнение. Удалены соответствующие настройки и ограничения
  очереди. Владение, Stop, generation, project scope и cleanup fencing сохранены.
- Регистрация блокировки задачи получает долговечное подтверждение и отдельную
  область координации; незавершённая другая control-операция ей не мешает.
- В общем чате фактическое решение C4 обновляет контекст агента и сохраняется
  для следующего сообщения. Состояние предложений восстанавливается из storage
  при пагинации и обновлении истории. Старый `pending` receipt не является
  основанием сообщать об ожидании после применения пакета.
- Служебная передача контекста не запускает новый ход при гонке с завершением,
  не оставляет поздний ownership grant и не создаёт пользовательский пузырь.

Контракты: [sidebar и лента](sidebar-feed-refinements.md),
[ресурсная политика](resource-execution-policy.md),
[C4 в общем чате](project-chat-c4-decisions.md).

Локально прошли production-сборка, TypeScript/Svelte, адресные тесты изменённого
кода, ESLint, форматирование и проверка размеров модулей. В отдельном штатном
Electron на настоящем снимке Cat-pilot проверены ID, диск/подсказка лимита,
раскрытие трёх файлов и отсутствие настройки параллельных запусков.

Живая работающая задача для проверки иконки отсутствовала; окно запуска
не открывалось, поскольку это изменило бы порядок задач. Миграция старого
BuildKit builder и новый live-сценарий доставки решения агенту не прогонялись.
Claude SDK сохраняет `shouldQuery: false` для следующего querying input и
не гарантирует перегенерацию уже идущего ответа; перед финальным утверждением
инструкции требуют актуального чтения C4.

Полный CI и шесть установщиков проверяются штатным workflow перед публикацией.
Pins Codex/Claude, SDK и версии пакетов адаптеров сохранены относительно 2.2.34;
новый успешный canary этим документом не заявляется. Установка выполняется
только опубликованным Windows x64 payload после сверки SHA512 и размера,
с сохранением предыдущего приложения и пользовательских данных.
