# BA-1: контракты встроенного агента

Дата: 31.10.2026. Область: контракты и регистрация. Дополнение BA-2:
[ядро lifecycle](builtin-agent-runtime.md); внутренний model loop добавлен в [BA-4](builtin-agent-models.md), продуктовый host ещё не подключён.
Основание: [ADR-0047](adr/0047-builtin-agent.md) и [план](builtin-agent-plan.md).

## Регистрация и поставка

Единственная точка подключения — `packages/agents/src/registrations.ts`.
В BA-1 запись `skaro` была `contract-only`. После BA-2 она имеет
`stage: runtime-core` и `delivery.kind: bundled`, с настоящими пакетами
`@skaro/agent-runtime`/`@skaro/adapter-skaro` и внутренним lifecycle-запуском.
UI-метаданных, npm pin или загрузки нет. Продуктовый запуск/выбор такого ID
отклоняется с `model-host-not-connected`; неизвестный ID — с `Unknown agent`.

`agentRegistration` возвращает декларацию поставки. `agentDefinition`,
`AGENT_IDS` и каталог работают только с исполняемыми регистрациями.
Контрактные записи не появляются в настройках, task/chat-контроллерах,
диагностических probes или updater. Переход к основному агенту отложен до BA-9.
Существующие IDs, порядок каталога и выбор владельца сохранены.

Claude Code/Codex объявляют `delivery.kind: managed-npm`: закреплённые версии,
размер и вычисление платформенного npm-пакета находятся внутри этой поставки.
Установщик, авторизация и native worker продолжают использовать прежние
адаптеры. Bundled-поставка принципиально не является успешной пустой установкой.

`BuiltinAgentReadiness` разделяет наличие runtime и настроенного маршрута.
Наличие бинарника не подтверждает API-подключение. Этот контракт пока не включён
в `AgentManager` и не представляет новые продуктовые состояния UI.

## Подключения и маршруты

Публичные DTO находятся в `packages/timeline/src/builtin-model.ts`:

- Connection: устойчивый ID и ревизия, connector, точный endpoint, версия
  API-профиля, ссылка на credential, несекретные настройки и routing policy.
- Model: пара connectionId/modelId. Производитель и семейство — метаданные,
  фактический upstream сообщается отдельно в результате запроса.
- Route: точные connectionId/modelId, параметры и upstream policy с ревизией.
- RouteSnapshot: копия маршрута, endpoint и ревизий без credential/settings;
  последующие изменения конфигурации не переписывают снимок запроса.
- ModelResponseProvenance: фактически сообщённые модель, upstream, request ID,
  usage и стоимость; неизвестные значения имеют `null`.

`snapshotRoute` отвергает неизвестные и неоднозначные IDs, несовместимые версии
профилей, некорректные ревизии и расширение routing policy подключения.
Endpoint должен быть HTTPS без userinfo, query или fragment; ключи передаются
через credential-порт. Нативные auth headers не являются настройками подключения.
Параметры/настройки должны проходить несекретную схему коннектора в BA-4;
TypeScript DTO сам по себе не является защитой от произвольного ввода.

Политика по умолчанию не допускает fallback, требует поддержки переданных
параметров и запрещает сбор данных. Restricted allowlist не расширяется
маршрутом. Автоматическая замена модели или подключения отсутствует.
`requireRouteCapabilities` требует подтверждённые возможности именно для
переданного снимка маршрута. Каталожное утверждение, другой маршрут или
устаревшая конфигурация не допускают обязательную операцию.

Исходные профили: `openai.responses`, `anthropic.messages`,
`deepseek.chat-completions`, `openrouter.chat-completions`, ревизия 1.
Все имеют `implementation: pending`; `requireImplementedApiProfile` отклоняет
их продуктовый допуск до закрытия приёмки. BA-4 добавляет сетевые коннекторы
и каталоги; фактическая проверка OpenRouter и отсутствие direct live описаны
в [моделях](builtin-agent-models.md). Расширение задаётся отдельным профилем
с connector/revision; совпадение HTTP-схемы не доказывает совместимость.

## Host-порты и безопасность

`packages/timeline/src/builtin-host.ts` определяет порты без Node/Electron/UI:

| Порт | Ответственность |
| --- | --- |
| processes | Запись PID/birth/platform до допуска, проверка/отзыв lease, подтверждение выхода дерева |
| credentials | Краткоживущий доступ коннектора к ключу только своего connection/endpoint/revision |
| operations | Каталог схем и вызов существующих MCP handlers в привязанном host scope |
| events | Подтверждаемая доставка версионированных событий с eventId/sequence |
| environment | Чтение штатного cwd, прав, проверенной sandbox-границы и сервисов |
| acceptance | Чтение актуальной приёмки, решений, C4 и возможности продолжения |

`SkaroScope` перенесён в общий контракт и реэкспортируется MCP без изменения
полей или обработчиков. Runtime не передаёт scope в отдельных операциях:
host связывает его с сессией, повторно проверяет schemas/availability/допуск
и сохраняет прежние подтверждения. `submit_result`/`merge_task` остаются
существующими операциями. Порт приёмки не меняет статусы и не создаёт очередь.

ProcessAdmission — отзывной lease с sessionId/generation; он не доказывает
наличие sandbox. После отмены host обязан отклонять новые действия.
Интерфейсы задают обязательства реализации BA-2/BA-3/BA-7.
Реализованное ядро процесса, журнала и восстановления описано отдельно в
[BA-2](builtin-agent-runtime.md); scoped operations и sandbox ещё не реализованы.

`builtin-credentials.ts` разделяет привилегированный CredentialVault и порт
коннектора. Решение хранения: DPAPI на Windows, Keychain на macOS,
Secret Service на Linux. Неподдержанное хранилище, включая `basic_text`,
означает отказ без plaintext fallback. Реализация и пределы защиты —
[credential vault](builtin-agent-credentials.md); Windows DPAPI проверен,
macOS/Linux ещё не прошли нативную приёмку.

Ротация — атомарный replace с ожидаемой ссылкой/ревизией, отзыв старых lease
до возврата новой ссылки. Смена connection/endpoint требует явной привязки.
Коннектор получает bytes только на время callback; реализация очищает их
после завершения/ошибки. Секреты запрещены в renderer-каталоге, журнале,
диагностике, `.skaro`, Git, ошибках и общем env команд. DTO и комментарии
не заменяют проверку этих гарантий после реализации vault и transport.

## Версии и release manifest

Host, события и проектор имеют версии формата 1; журнал после BA-3 — schema 2
(`BUILTIN_CONTRACT_VERSIONS`). Старый журнал schema 1 требует явной миграции.
Несовпадение любого формата отклоняется;
миграции должны быть явными, с сохранением исходной истории. Native continuation
остаётся привязанным к своему маршруту и версии профиля.

После BA-2 runtime получает semver из настоящего package.json и сохраняет его
в первичном журнале; поставляется только вместе с соответствующим выпуском Skaro.
В BA-1 фиктивной версии runtime не вводилось. BA-4 использует native fetch
закреплённого Node/Electron без новых SDK. Версии API-профилей и формата журнала
сохраняются отдельно; текущая приёмка перечислена в [моделях](builtin-agent-models.md).

Публичный release manifest остаётся `schema: 1`. Состав managed-npm компонентов,
alias `claudeSdk`, SDK pins, integrity и шесть OS/arch не изменены.
Контрактная bundled-запись не добавляет npm-артефакт или адаптер в metadata
действующего выпуска. Runtime будет частью app payload с его существующей
проверкой целостности; отдельная публичная схема обновления не вводится.

## Фактические проверки и ограничения

Результаты этой реализации перечисляются в разделе BA-1
[плана](builtin-agent-plan.md#результат-ba-1-31102026).
Повторная установка/интерактивный вход внешних агентов, выдача ключа, запросы к API,
изоляция процесса и поставка работающего bundled runtime требуют отдельных
проверок. Они не подтверждаются тестами DTO или успешной сборкой приложения.
