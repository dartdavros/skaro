# BA-2: процесс, журнал и lifecycle

Дата: 31.10.2026. Реализовано ядро lifecycle; полная приёмка BA-2 пока не закрыта.
Инструменты и Windows command backend добавлены в [BA-3](builtin-agent-tools.md).
Основание: [ADR-0047](adr/0047-builtin-agent.md), [план](builtin-agent-plan.md),
[контракты BA-1](builtin-agent-contracts.md).

## Границы реализации

`packages/agent-runtime` содержит журнал, восстановление, последовательную
обработку команд и проектор. `packages/adapter-skaro` запускает настоящий
дочерний Node-процесс и реализует транспорт `AgentSession`. Зависимости:
adapter → runtime → timeline; Electron/UI в runtime не импортируются.

Единственная регистрация `skaro` находится в прежнем `registrations.ts`,
определение — в адаптере. Её этап — `runtime-core`, причина недоступности
продуктового запуска — `model-host-not-connected`. В реестре есть
внутренний `startBundledSession` и проектор; npm-установки, подписки, логина
и UI-метаданных у встроенного агента нет. Продуктовый каталог и выбор
по умолчанию не изменены. Release manifest остаётся v1.

BA-3 добавил файловые/процессные инструменты; BA-4 — коннекторы и внутренний
model/tool loop. Контекстный compact и подключение к задачам/чатам ещё отсутствуют.
Вызов `send`/`steer` сохраняет настоящий ввод и ошибку неподключённого model host,
но не отправляет запрос модели и не создаёт успешный ответ.
`compact`, effort без схемы коннектора и защищённые ответы
на секретные вопросы дают явный отказ. Это не готовый к задачам агент.

## Штатный процесс и допуск

Сборка Electron теперь включает `agent-runtime-worker.js`. Внутренняя точка
`native/bundled.ts` передаёт `BuiltinSessionStart` существующему native worker.
Он через реестр создаёт адаптер, который запускает отдельный процесс;
в Electron используется `ELECTRON_RUN_AS_NODE=1`.

Дочерний процесс ждёт admission-сообщения, не открывая журнал. До него адаптер
получает OS birth identity и вызывает существующий `processStarted`.
Native worker сохраняет прежний gate с подтверждением main-процесса:
запись PID/birth/platform должна завершиться до разрешения действий.
Нет ownership callback — нет запуска сессии. При отмене startup сообщение
допуска не отправляется, процесс завершается и его выход проверяется.

Общий OS-код перенесён из desktop в runtime; desktop реэкспортирует прежний
API. Остановка проверяет birth identity, не убивает процесс с переиспользованным
PID и использует прежний механизм завершения дерева. Для bundled worker
сначала запрашивается сохраняемое закрытие, затем проверяется выход OS-процесса;
есть ограниченное ожидание и принудительное завершение при необходимости.
Закрытие во время startup передаёт AbortSignal до готовности сессии.

Окружение дочернего runtime содержит только перечисленные системные переменные
и флаг запуска Node. Произвольные env, API-ключи и конфигурация host-приложения
не наследуются. Секреты API должны поступать через credential-порт BA-1
после реализации vault/коннекторов; здесь он не заменён переменной окружения.

Это process ownership, а не доказательство sandbox. Инструментов, создающих
рабочие дочерние процессы, пока нет; их отмена и подтверждение выхода дерева
проверены в BA-3 для Windows, без заявления о security sandbox.

## Один первичный журнал

Host задаёт путь JSONL в контейнере истории сессии. Runtime владеет записью
этого файла. Запись содержит schema/sessionId, последовательность, устойчивый
ID, время, цепочку hash/previous, факты и результат команды. Семантическая
версия runtime берётся из настоящего package.json и сохраняется при создании.
Несовместимые версии формата или runtime требуют явной миграции.

Факты и результат одной команды пишутся одной строкой; `fsync` предшествует
ответу, событиям ленты и допуску следующего действия. Изменяемые входные объекты
копируются до записи. Ошибка записи останавливает дальнейшие записи этого
журнала. Повтор command ID с тем же содержимым возвращает сохранённый результат;
повтор ID с другим содержимым отклоняется. Повтор не создаёт новый ход или ответ.

Соседний SQLite index содержит только владение и восстанавливаемый checkpoint.
Владение захватывается транзакцией с проверкой PID/birth; живого владельца
нельзя заменить вторым runtime. После смерти процесса lease может быть
перехвачен только после проверки OS identity. Checkpoint не является отдельной
историей: при открытии состояние заново строится из JSONL.

Оборванный незавершённый хвост без newline отсекается до последней полной
записи. На Windows для этого нужен отдельный дескриптор `r+`: append-only
дескриптор не допускает truncate. Полная повреждённая строка, разрыв
последовательности, чужая sessionId или неверная hash-цепочка дают отказ;
такие факты автоматически не удаляются. Hash-цепочка проверяет целостность,
но не является подписью от владельца.

`SkaroProjector` выводит канонические TimelineEvent из фактов этого журнала.
Восстановление не воспроизводит инструменты или модельные запросы. Raw callback
адаптера передаёт копии уже записанных фактов; при продуктовой интеграции BA-7
он не должен повторно писать в первичный файл или становиться второй истиной.
Подключение контейнера к обычным task/chat histories ещё не выполнено.

## Восстановление и управление

Сохраняются выбранный маршрут и права, пользовательские входы, открытые
взаимодействия, ответы, явная остановка/закрытие, rewind boundary и факты эффектов.
Неизвестный исход допускает только дальнейшее выяснение по фактам, не повтор.
Незакрытый effect intent после перезапуска становится `unknown`; новый ход
и смена контекста при таком эффекте блокируются. Исполнение инструментов и
механизм разрешения неизвестного результата входят в последующие этапы.

`respond` валидирует открытое взаимодействие и сохраняет ответ/закрытие вместе.
Повторная доставка той же команды возвращает прежний результат. Транспорт
секретных ответов ещё не реализован; такой ввод отклоняется до записи и даже
до сохранения его fingerprint. Реальные вопросы модели появятся с loop/tools.

Смена модели выполняется по точному ID маршрута из `availableRoutes`,
предоставленных host. Произвольное имя модели не выводит подключение и не
выбирает upstream. `setRoute` принимает новый проверенный host snapshot.
Изменение маршрута и conversation rewind запрещены при открытом
взаимодействии или незавершённом эффекте и сбрасывают native continuation.
Продолжение с другого маршрута нельзя сохранить как совместимое.

Conversation rewind сохраняет границу до известного пользовательского ввода
и событие ленты, не удаляя исторические факты. Он не меняет файлы.
Рабочий контекст и реальное продолжение после rewind/compact проверяются
в BA-4/BA-5; успешный compact сейчас не объявляется.

## Проверки и незакрытая приёмка

Фактические команды и результаты фиксируются в [плане](builtin-agent-plan.md).
Тесты журнала проверяют настоящие файлы и SQLite, а процессные тесты — настоящие
дочерние процессы и OS identity. Проверки состояния interaction/effect intent
проверяют контракт журнала; они не доказывают исполнение инструментов или
генерацию вопросов моделью. Сетевых заглушек и модельных ответов нет.

BA-4 отдельно проверил отмену настоящего OpenRouter streaming и restart/replay
двух model/tool цепочек; границы — в [моделях](builtin-agent-models.md).
Не закрыты: отмена модельного вопроса в продуктовом workflow;
живые continuation прямых API; продолжение после compact/rewind;
восстановление внутри task/chat
workflow и упаковка на остальных OS/arch. UI и браузер приложения не менялись
и не проверялись этим этапом.
