# C4-2 — независимая проверка и синхронизация архитектуры

Дата: 13.11.2026. Этап реализован в рабочем дереве; локальная приёмка 7/7
закрыта с перечисленными ниже границами. Основание —
[план C4](archiagent-c4-plan.md), [контракт](c4-workflow.md).
Коммит и релиз Skaro не выполнялись.

## Реализация

Протокол `impact-v1` выбирается явно и закрепляется до dispatch конкретного
запуска. Handoff наследует его; изменение настройки проекта не меняет старые
запуски и пакеты. Отсутствующая привязка сохраняет `package-v1`, неизвестная
версия останавливает операцию. После приёмки default Cat-pilot возвращён
в `package-v1`; T-012/T-013 сохраняют собственную привязку `impact-v1`.

Рабочий агент запрашивает проверку и завершает turn. Хост самостоятельно
читает настоящий checkout, Git, требования, спецификации, архитектуру, ADR,
локальную область модели и зависимости. Observation остаётся непроверенным
свидетельством: `aligned` рабочего агента не даёт допуска. Отдельный native
reviewer получает ограниченные исходники и контекст без инструментов записи.
Модель и процесс проходят общий ресурсный допуск до запуска; исходный процесс
освобождает ёмкость. Результат связан с run, intent, fingerprints, native session
и хешем физического лога. Параметры бюджета передаются native adapter.

SQLite хранит CAS-состояния queued/running/verified/failed/uncertain и доставку
результата. Неопределённый исход не запускает модель повторно: сначала
останавливается подтверждённый старый процесс, требуется новое намерение
владельца. Stop ждёт физического завершения reviewer. Notice и продолжение
имеют устойчивые идентификаторы; продолжение проверяет актуальное намерение.
Новые renderer-компоненты, тексты экранов и layout не добавлялись: используются
существующие notice, предложения и механизм решения.

Существенный пакет сохраняет точное решение владельца. Необязательность
подтверждается независимым review именно этого пакета/run; один boolean её
не заменяет. Accepted и legacy pending продолжают блокировать сдачу. Проверка
результата вновь сверяет физические исходники и смысловой контекст, пути,
полноту родителя и planned/current. Техническое переименование доказывается
Git R100, равенством blobs и точной заменой ссылок; оно не реализует planned.

Локальный fingerprint не зависит от посторонней ревизии модели, отметок
критериев и добавленного итогового резюме задачи. Пересечение локальной области
меняет fingerprint. Three-way rebase сохраняет независимые изменения,
отказывает при пересечении и изменённом значимом порядке. Исходный согласованный
пакет неизменяем; производный кандидат сохраняется отдельно перед записью.
Записи сериализованы по проекту, документы и модель используют штатный журнал
с model-last и проверкой точного хеша пакета, а не одного ID.

## Аварийное восстановление

В T-012 наблюдатель пропустил окно аварийного прерывания. Обычная публикация
и повтор прошли, но не были засчитаны как crash-during-write. Для настоящего
обрыва владелец отдельно разрешил T-013:
[согласованный объём и результат](archiagent-c4-2-next-acceptance.md).

Перед сдачей проверена долговечная SQLite-копия: integrity `ok`, fsync и SHA256
`ae54ddf8566185c52d4adeabb8aaf343d36111759a31a1e6b1049fe0754e37a5`.
Наблюдатель был вооружён до создания services. После фактического обновления
Git ref, при ещё существующем настоящем publication journal и prepared
completion operation, он синхронно сохранил checkpoint и вызвал `app.exit(73)`.
Искусственный журнал не создавался.

На следующем запуске штатное восстановление сверило журнал с checkpoint,
реальный commit и index, завершило проекцию операции
`4415469c-1d47-4f6c-a92e-f2d6aab9fc84`, историю и C4 до ревизии 3.
Повторная сдача обеих задач вернула прежний commit без новой записи merge,
изменения модели или повторного model call. Все 9 вопросов, planned/current
и посторонние файлы сохранены.

Обрыв выявил оставшуюся transient publication reservation. Production recovery
теперь освобождает только retained execution reservation завершённой операции
после проверки ancestry commit, без locks и активных model/environment/build/
review costs. Финальная живая проверка: активных execution reservations 0.
Физический временный merge checkout сохранён: освобождение ledger reservation
не выдаётся за удаление checkout или освобождение дискового пространства.

## Критерии и границы доказательств

| Критерий | Проверка |
| --- | --- |
| Принятая реализация без C4-вопроса | Реальные T-012/T-013, независимый native review и штатная сдача |
| Новый контракт не скрыт технической синхронизацией | Строгая классификация DTO, проверка смысловых полей и host-proved preservation |
| Optional не блокирует, обязательное блокирует | Целевые SQLite protocol metadata tests; реальный optional/contradiction workflow отдельно не создавался |
| Независимые правки сохраняют review, пересечение отвергается | Реальная модель Cat-pilot прочитана; контрфактические изменения только в памяти, rebase tests документированной модели Skaro |
| Пути, неполный родитель, planned/current | Настоящий checkout и валидаторы; отсутствующий путь/неполный родитель только в памяти; обе реальные публикации |
| Повтор и прерывание | Реальный T-013 publication journal/ref checkpoint, штатное recovery, повтор T-012/T-013 |
| Разделение протоколов | Immutable binding, unknown fail closed, legacy key не заполнен новым review, default восстановлен |

Целевые проверки: 9 файлов, 17 passed. Штатная сборка main/preload/renderer,
desktop TypeScript/Svelte, целевой ESLint/Prettier, whitespace и NO GOD проверены.
Полный suite не запускался. В сборке остаются предупреждения сторонних
зависимостей; новый UI и изменение manifest/lockfile этим этапом не добавлялись.

Проверены Windows, Codex и разрешённый контур Cat-pilot. Проверки macOS/Linux,
других adapters, старого бинарника, аппаратного power loss, полного ручного
аудита и миграции настоящих legacy pending/accepted не заявляются.
Общие UI-сценарии, ручной аудит и миграционная приёмка относятся к C4-3;
RC-4 и AG-1 остаются отдельными незавершёнными этапами.
