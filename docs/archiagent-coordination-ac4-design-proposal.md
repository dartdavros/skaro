## Предлагаемое представление

В правой части существующей TitleBar, перед кнопкой фоновой работы, появляется
компактная кнопка **«Требуют ответа · N»** текущего проекта. Существующие вкладки,
навигация, модалка фоновой работы и порядок разделов сохраняются. При нулевом
счётчике кнопка остаётся нейтральной; при ожидании используется существующий
цвет `--sk-link`. Новые иконки, палитра или отдельный раздел навигации не нужны.
На Home/Settings без активного проекта проектная кнопка отсутствует.

Кнопка открывает одну Modal шириной 720 px, как существующая BackgroundModal.
Заголовок — **«Требуют ответа»**, подзаголовок — имя проекта и число ожиданий.
Внутри — вертикальная очередь прежних карточек взаимодействий: источник,
суть вопроса/действия, причина и последствия, существующие варианты ответа.
Первое доступное разрешение сохраняет primary-кнопку; права не расширяются.
Вариант `allow_session` не появляется у одноразового controller approval.

Крестик, Esc, backdrop и **«Позже»** закрывают окно без ответа. Ожидание и
набранный безопасный черновик сохраняются; фокус возвращается на кнопку очереди.
При смене проекта окно закрывается, счётчик и содержимое переключаются на новый
project ID. Возврат к проекту не открывает окно автоматически и не теряет запрос.
Независимая работа продолжается. Одновременно открыта только одна проектная
модалка: переход «Фоновая работа → Открыть решение» заменяет содержимое окна.

### Связь с лентой

Ожидающие действия остаются в прежней области PendingActions над вводом, вне
истории/файлов. Проектное окно — ещё одно представление того же decision ID.
Ответ из окна обновляет карточку в ленте; ответ в ленте обновляет очередь.
Завершённый ответ появляется в истории без действующих кнопок. Переход к
исходной задаче/чату не создаёт нового запроса и не вызывает continuation сам.
Вопросы, C4/документы, формы, план, вход и слияние сохраняют прежние карточки
и единственный штатный путь ответа; новое универсальное разрешение не вводится.

## Визуальный язык и геометрия

Используются текущие Nunito Sans, токены `--sk-*`, Modal, Button, карточки ленты,
LoadingIndicator/LoaderCircle и существующие Lucide-иконки. Тёмная палитра
в макете соответствует текущему baseline; новая тема не проектируется.

| Часть | Предлагаемая геометрия |
| --- | --- |
| TitleBar | Существующая высота 42 px, прежние кнопки и вкладки |
| Modal | 720 px, максимум доступной ширины, radius 14 px, padding 20 px |
| Очередь | В макете 480 px под содержимое; высота ограничивается доступным пространством настоящего окна, прокручивается только тело |
| Карточки | Прежняя структура, radius 10 px; варианты ответа остаются частью карточки |
| Загрузка/ошибка/отправка | Размер очереди сохраняется; под короткий статус карточки зарезервирована область, индикатор не замещает весь layout |
| Footer | Всегда видим, вне прокрутки; «Позже» или «Закрыть» для завершённого состояния |
| Узкая ширина | Элементы переносятся; прокрутка очереди не затрагивает header/footer и ввод исходной ленты |

Новая оболочка приложения не предлагается: фоновые документы и две вкладки
в интерактивном макете служат контекстом для проверки проектной принадлежности.

## Матрица состояний решений

Все новые формулировки ниже согласованы владельцем для AC-4. Текст вопроса, причина и варианты берутся из самой записи,
не генерируются новым renderer из предположений.

| Состояние | Отображение | Доступные действия |
| --- | --- | --- |
| Загрузка | LoaderCircle в выделенной области, «Загружаем…» | Закрыть/отложить; ответ недоступен до проверки актуальности |
| Ожидание/готовность | Прежняя карточка, источник и последствия | Только варианты исходного запроса |
| Отправка | «Сохраняем ответ…» в reserved status области | Кнопки ответа disabled, повторный клик не создаёт действие |
| Ошибка сохранения | «Ответ не сохранён. Попробуйте ещё раз.» | «Повторить» с тем же decision ID/ключом ответа; ожидание не теряется |
| Запрос изменился | «Запрос изменился. Обновите его.» | «Обновить» читает актуальную запись; старое действие не подтверждается |
| Нативное разрешение истекло | «Разрешение истекло. Нужен новый запрос.» | Только «Открыть задачу»; «Разрешить» отсутствует, новый запрос не создаётся автоматически |
| Ответ сохранён | «Ответ сохранён.»; исключён из числа ожидающих | «Открыть задачу», «Закрыть»; активных вариантов ответа больше нет |
| Запрещено | «Действие запрещено.»; исключён из числа ожидающих | Переход к источнику и закрытие; запрет не превращается в повторное согласие |
| Пустая очередь | «Нет ожидающих решений» | Закрыть; счётчик 0 |

Двойной ответ, конкурентный ответ и проверка expiry/revision обеспечиваются
общим backend, не локальным `disabled`. Дизайн показывает итог, но не заменяет
проверки полномочий, доставки и фактического единственного эффекта.
Секретные поля сохраняют прежний защищённый ввод; их значения не попадают
в счётчики, фоновые события, проекции очереди или общедоступные summaries.

## Фоновая работа и долговечный журнал

Существующие **«Сейчас»**, **«Недавно»**, строки BackgroundRow, LoaderCircle и
иконки состояний сохраняются. Подзаголовок задаёт проектную принадлежность.
Добавляются только важные подтверждённые события: исправлено окружение,
разблокирована задача, освобождён собственный ресурс, запрошено решение.
Под строкой — причина/исход и связанная задача или ресурс. Технические попытки
одной операции объединяются; не каждая попытка становится уведомлением.

Ожидающее решение имеет ссылку **«Открыть решение»** на ту же запись очереди.
В footer предлагается **«Журнал проекта»**: та же Modal показывает долговечную
историю с группировкой по дате и возвратом **«Недавняя работа»**. Исторический
факт называется «Запрошено решение владельца», а не выдаётся за всё ещё
активное ожидание. Исход после очистки временного списка остаётся в журнале.
При большом архиве нужны адресная пагинация и существующая Button «Показать ещё».
Подтверждённые исходы не заменяются предположением по exit code или пустому DU.

Загрузка сохраняет область модалки; ошибка чтения — **«Не удалось загрузить
события.»** и **«Повторить»**. Пустое представление — **«Событий пока нет»**.
Исход ошибки/отмены операции сохраняет прежнюю семантику, а не превращается
в success. Для общей непроектной работы нужна отдельная явная область данных;
её нельзя приписывать активному проекту по имени в тексте строки.

## История подготовки макета до утверждения

Интерактивный макет показан в текущем чате. Его примеры текста и времени
иллюстрируют дизайн; это не реальные incidents/tasks/events Cat-pilot и не
fixtures/seed для приложения. Прототип не вызывает backend/API и не изменяет
проекты. Предпросмотр — локальный файл, временный HTTP-сервер не запускался.

Проверены Chromium-render и взаимодействия самого макета: закрытие сохраняет
ожидание и черновик выбора, смена проекта не показывает чужую очередь, ответ отражается в ленте,
pending область находится над вводом, отправка блокирует повтор, expiry убирает
разрешение, фоновые события переходят в журнал. Девять состояний очереди
сохраняют одинаковый размер Modal; горизонтального выхода элементов нет на
ширинах 1100, 736, 360 и 320 px. Desktop/узкий/background виды просмотрены визуально.

На момент показа это **не** было browser-приёмкой AC-4 в штатном Cat-pilot.
После прямого утверждения владельца начаты реализация и проверки приложения.
Исторические проверки макета не заменяют результаты штатной приёмки.
