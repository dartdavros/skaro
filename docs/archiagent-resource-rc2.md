# RC-2 — общий диспетчер ресурсов и приёмка

Статус на 12.11.2026: **завершён, семь критериев приняты**. Диспетчер подключён
к исполнителям приложения. Пройдены целевые проверки, сборка и сквозной
сценарий с настоящим агентом, проверкой и ручным просмотром Cat-pilot.
Это приёмка RC-2 в рабочем дереве, а не выпуск и не общая приёмка AG-1.
Очистка кешей/данных RC-3 и расширенная recovery-проверка RC-4 остаются открытыми.

## Допуск и исполнители

Один `ApplicationResources` создаётся в `app-services.ts` до recovery и
проектных координаторов. Проекты используют общий `ResourceManager` и журнал
`resource_leases` (миграция 11). Проверочный scope задаётся до создания сервисов.

| Исполнитель | Граница допуска |
| --- | --- |
| Task, chat, integration | Процесс и первый ход резервируются до создания native worker и provider thread; следующие ходы проходят новый admission |
| Native commands, setup и зависимости | До передачи управления агенту резервируется бюджет работы; он удерживается до завершения команд, даже после окончания хода модели |
| Worktree и материализация истории | `ResourceGit` резервирует стоимость до создания checkout и повторно проверяет право непосредственно перед `worktree add` |
| Проверки задачи и интеграции | Общая фаза `build`, включая штатные shell-команды |
| Окружение | Отдельный runtime lease плюс фаза подготовки/копирования/сборки; допуск до запуска сервисов |
| Ручной просмотр | Отдельный `review` lease, связанный с текущим generation; запуск окружения также требует допуска |
| IPC и MCP | Доверенный host-контекст владельца, intent, отмены и актуального права; чтение с материализацией тоже проходит диспетчер |

`RunQueue` сохраняет порядок операций одного владельца. При внешнем admission
она не удерживает слот модели на всё время окружения или просмотра. Слоты
model/build/environment/review независимы. Работа с той же проверяемой копией
по-прежнему сериализована. Аккаунт определяется доверенными настройками сессии;
учитываются его параллельность и полученные от провайдера quota/reset.
Credentials в leases не записываются.

## Бюджеты и измерения

Политика хранится в `resources.policy.v1`, оценки — в `resources.costs.v1`.
Значения по умолчанию:

| Работа | RAM | CPU, ядра | Диск | Слот |
| --- | --- | --- | --- | --- |
| Worktree | 128 MiB | 0,5 | 512 MiB | — |
| Native process | 512 MiB | 0,25 | 128 MiB | — |
| Модель | 128 MiB | 0,25 | 0 | model |
| Работа / build | 512 MiB | 1 | 512 MiB | build |
| Окружение без известных лимитов | 1 GiB | 1 | 1 GiB | environment |
| Просмотр | 0 | 0 | 0 | review; окружение отдельно |

Model-слоты берутся из `runs.slots` (по умолчанию 3); environment/build/review
имеют по 3 слота. Резерв хоста: 1 GiB RAM, 1 GiB на файловую систему, 0,5 CPU.
Измерения действительны 5 секунд; ожидания перепроверяются каждые 2 секунды.

Host-адаптер использует свободную RAM, доступные CPU и `statfs` реальных путей.
Диск учитывается по идентичности файловой системы: Docker storage и worktree
на одном томе конкурируют за общий физический бюджет. Docker-адаптер читает
`info`, `stats` и файловую систему локального хранилища; резерв VM — максимум
из 256 MiB и 10% RAM, плюс 0,5 CPU. Наблюдаемое потребление и выданные резервы
учитываются консервативно.

Канонический `docker compose config` даёт лимиты RAM/CPU сервисов и число
реплик. Каждый сервис без лимитов получает консервативную оценку; явная
настройка стоимости окружения имеет приоритет. В Cat-pilot проверена стоимость
64 MiB / 0,25 CPU, совпадающая с Compose-ограничениями.

Неизвестные или устаревшие метрики не открывают допуск. Нераспознанное/удалённое
Docker-хранилище не получает дисковый допуск. Для известного локального пути
предусмотрена настройка `resources.dockerDataPath`. Docker Desktop проверяет
существующие стандартные пути из
[документации Docker](https://docs.docker.com/desktop/settings-and-maintenance/backup-and-restore/);
при пользовательском расположении нужен известный путь. Измеряется свободное
место хостовой файловой системы, содержащей VHD/raw. Свободное место внутри VHD
и его уплотнение этим измерением не подтверждаются.

Бюджет произвольных CLI-команд резервируется до их запуска как стоимость работы
агента. Это оценка admission, а не принудительный OS-лимит памяти или гарантия
максимального размера зависимостей. Compose дополнительно ограничивает
контейнеры. Полная калибровка расходов относится к RC-4.

## Leases, остановка и освобождение

- `BEGIN IMMEDIATE` атомарно проверяет бюджет, выдаёт lease и регистрирует
  потребителя RC-1. Совместимость и исключительность учитывают generation;
  снятие потребителя активного lease или смена поколения отклоняются.
- Атомарное разделение model/work сохраняет суммарную стоимость резерва.
  Повтор разделения и устаревшие revision/generation отклоняются.
- FIFO защищает старые запросы при конкуренции за исчерпанный ресурс, включая
  аккаунт и общий диск Docker/host. Независимый preview может получить свой
  слот, пока другой запрос ждёт build-слот.
- `waiting_resource` / `waiting_quota` и причина сохраняются; события
  `resource_admission` пишутся в журнал. Новых UI-состояний не добавлено.
- Stop окончательно снимает ожидание: освобождение бюджета не оживляет
  `stopped_by_owner`. Явное продолжение получает новый intent, проверку права,
  admission и штатную проверку готовности окружения.
- Завершение хода освобождает model, завершение команд — work. Простой native
  process закрывается через 30 секунд без активной работы. Вопрос/разрешение
  не удерживает ненужные резервы модели и работы.
- Запущенные процессы/контейнеры удерживают резерв до подтверждения остановки.
  Shell cancellation ждёт завершения дерева с проверкой идентичности процесса;
  одного AbortError недостаточно для освобождения.
- Завершение независимого агента не снимает просмотр. Завершение просмотра
  останавливает его процессы/сервисы и затем освобождает leases; данные остаются.
- При restart ожидания отменяются с `restart_requires_readmission`, прежние
  активные удержания сохраняются до сверки. TTL/restart не разрешает повторить
  эффект или объявить ресурс освобождённым.

Живая проверка выявила и позволила исправить наследование `Path` в Windows,
создание пустого provider thread до admission и Compose identity при общем
`COMPOSE_FILE` с отдельным task worktree. Guard требует точный состав объявленных
Compose-файлов, собственного ports override, project label и рабочей директории;
имя контейнера само по себе не даёт права остановки.

Модули разделены по ответственности: `application-resources`, `resource-manager`,
`resource-execution`, `resource-model-work`, адаптеры `resource-budget` /
`resource-docker-*` / `resource-environment-cost`, `native/resources`,
`resource-environment`, `resource-git`, core `resources/admission-*` и
`db/admission*`. Новых UI-компонентов и изменений baseline нет.
