# C4-1 — контракт влияния и классификация

Дата: 11.11.2026. Контрактный этап реализован и локально проверен в рабочем дереве.
Основание: [план C4](archiagent-c4-plan.md), [целевой процесс](c4-workflow.md).
RC-1 и AC-1 сохранены; коммит и релиз не выполнялись.

## Контракт

В `packages/core/src/c4/` добавлены отдельные модули `impact-contract`,
`impact-validation`, `impact-assessment`. Они экспортируются через core,
но не переключают действующий runtime и не записывают C4-пакеты.

`C4Impact.version = 1` содержит project/task/run, абсолютный checkout, Git base,
fingerprint изменений и локальной области, ожидаемую revision, требования,
элементы/связи, хеши источников, результаты проверок и расхождения с требованиями.
Полная модель в сообщении отсутствует. Путь источника должен быть относительным
без traversal; неизвестная версия, некорректные хеши и повторные ID отклоняются.
Fingerprint канонизирует множества ссылок и связывает все входы, включая run.

`C4ImpactFacts` — отдельный доверенный вход сервиса: наблюдённое evidence,
результат смысловой проверки, доказанные переименования и зависимости задач.
Его нельзя создавать простым копированием сообщения рабочего агента.
Сбор фактов из реального checkout и маршрут проверки реализуются в C4-2.
Значение `semanticEvidence: verified` в API не является проверкой само по себе.

Классификация сравнивает сообщение с наблюдением и фактическим содержимым
неизменяемого пакета. Категория агента не принимается как разрешение:

| Категория | Проверяемая граница |
| --- | --- |
| technical | Смысл документов/модели сохранён; допустимы проекции или узкая смена code-привязок с совпадающими хешами старого/нового файла и проверенной семантикой |
| decision | Изменились авторский текст, обязанности, требования, связи, состояния либо другие смысловые поля; недоказанное переименование также требует решения |
| optional | Нет необходимого изменения модели, обязательных требований и противоречий; идея не выдаётся за разрешённую запись |
| contradiction | Проверено расхождение с конкретным принятым требованием и источником |
| insufficient-evidence | Не хватает проверки, вход устарел/чужой, scope/revision не совпадает или обязательная область не имеет операции |

Оценка возвращает задачи, требования и код причины ожидания по пересечению
доверенных зависимостей. Независимые задачи в ожидание не включаются.
Это описание будущего gate, не изменение статуса задач или текущего UI.

Узкая операция содержит список изменённых сущностей/полей, локальную область
ревью, expectedRevision, fingerprints пакета/impact и устойчивый idempotency key.
Изменение входа меняет ключ; повтор не создаёт новое разрешение.
Разрешение пока всегда `pending`, протокол `impact-v1`, `mayApply = false`.
Автоприменение, журнал/CAS, policy и повторная сверка перед записью — C4-2.

Классификация не заменяет `inspectC4Model`, проверку документов, путей, родителей
и фактической реализации. Публикация `planned → current` не считается простой
сменой привязки и остаётся частью прежней проверяемой публикации с кодом.

## Совместимость и gates

`c4RunProtocol` разрешает протокол только по привязке к точным project/run.
Отсутствующая привязка означает `package-v1`, даже если будущая настройка проекта
выбрала новый режим. Чужой run и неизвестный протокол отклоняются.
Сохранение новой привязки до первого dispatch относится к включению в C4-2;
старые записи и настройки в C4-1 не мигрируются.

| Старое условие | До переключения | После проверенного переключения в C4-2 |
| --- | --- | --- |
| pending/accepted пакет задачи | Прежний запрет сдачи | Явное сопоставление с решением и зависимыми операциями; старое согласие не расширяется |
| review_c4 отсутствует/устарел | Прежний gate | Актуальное evidence и смысловая проверка локальной области |
| Необязательная идея | Прежний порядок пакетов | Отдельное предложение без блокировки независимой сдачи |
| Противоречие принятому требованию | Прежняя проверка | Ожидание только зависимых задач с точной причиной |
| planned ещё не опубликован | Прежняя публикация | Та же подтверждённая публикация с кодом без повторного архитектурного решения |

Старые MCP `propose_c4`/`review_c4` остаются прежними. Нельзя снять старый gate
одним новым DTO. Pending сохраняет решение ожидающим; accepted завершает прежнюю
журналируемую транзакцию либо фиксирует конфликт. ID, байты, source, состояние
и история пакета не переписываются. Отмена/замена создаёт отдельное решение.
Recovery использует закреплённый протокол операции, не текущую настройку проекта.
При откате неизвестный `impact-v1` должен остановиться, а не стать ручным согласием.
Запуск старого бинарника после будущего включения требует проверки совместимости
хоста в C4-2/C4-3; один helper не обеспечивает downgrade всего приложения.

## Проверки и ограничения

- Целевые `impact.test.ts` и `impact-live.test.ts`: 2 теста прошли.
  Проверены scope/fingerprint, отказ без evidence, зависимости, версии,
  протоколы, неизменность данных, категории и устойчивый ключ операции.
- В Cat-pilot нет C4-пакетов в workspace.db и legacy settings.
- По отдельному явному разрешению владельца прочитаны только пакеты Stolovka:
  48 записей, из них 47 applied и 1 rejected. Сравнение записей до/после прошло;
  приложение, миграция, recovery, агент, Git/Docker операции не запускались.
- Реальные пакеты содержат смысловые изменения. Техническая проекция проверена
  в памяти на неизменённом сохранённом снимке. Предикаты verified/conflict/optional
  в тесте являются проверкой классификатора, не новым ревью кода Stolovka.
  Живых pending/accepted среди этих 48 записей нет; их runtime recovery не проверялся.
- Сохранность старых pending/accepted обеспечивается границей этапа: прежние
  readers/writers/MCP/gates не изменены. Их миграционная приёмка остаётся C4-3.
- Первый запуск анализа истории превысил стандартные 5 секунд Vitest;
  явный timeout 30 секунд соответствует чтению реальной истории, повтор прошёл.
- `pnpm --filter @skaro/core typecheck`, целевые ESLint/Prettier и `git diff --check`
  прошли. NO GOD: максимальный новый модуль 148 строк, тест 145 строк.
  Manifest/lockfile и UI не изменены. Финальная `pnpm build` прошла:
  main, preload, renderer. Остались прежние предупреждения зависимостей
  об аннотациях Zod, неиспользуемых импортах SDK и eval в tree-sitter.

Повтор разрешённого read-only теста требует явного выбора источника:

```powershell
$env:SKARO_C4_IMPACT_DATA = "$env:APPDATA\Skaro"
$env:SKARO_C4_IMPACT_PROJECT = 'b1a0a1fc-5435-4b37-a30a-c2b3d6c06f1b'
pnpm exec vitest run packages/core/src/c4/impact.test.ts packages/core/src/c4/impact-live.test.ts
```

Mock API, fixtures, seed-проекты и временные серверы не создавались.
Полный suite не запускался. UI не менялся; browser-проверка не требуется этому
контрактному этапу. Вопросы C4 пока не исчезают из задач: это результат C4-2,
а ручной аудит и общий UI требуют C4-3/AC-4 и согласованного дизайна.
