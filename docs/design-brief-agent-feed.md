# Задание дизайнеру: агентская лента, вопросы, разрешения, модалка агента

**Что это.** Доработка агентских блоков под то, что Claude Code и Codex отдают на самом деле. Технический разбор — в [agent-output.md](agent-output.md). Здесь — только то, что нужно нарисовать.

**Где.** Экран «Задача» (лента запуска), экран «Чат» (лента чата), поле ввода, модалка «Агент задачи». Остальные экраны не трогаем.

**Главное условие.** Ничего нового по визуальному языку. Каждый блок собирается из элементов «Инвентаря UI» и уже нарисованных блоков ленты. Если для чего-то в инвентаре нет элемента, новый элемент добавляется в инвентарь в том же стиле.

---

## 0. Правила, которые нельзя нарушать

Из инвентаря, для этого задания обязательно:

- **Цвета.** Синий `#2a52be` — только кликабельное и «требует внимания». Коралл `#e8875b` — команды и код. Зелёный — только «+» в диффе. Красный `#ef6a63` — ошибка и «−» в диффе (как на Обзоре). Жёлтый `#e0a33c` — предупреждение и рискованный выбор. Новых цветов нет.
- **Шрифты.** Nunito Sans — текст. JetBrains Mono — пути, команды, числа, ID.
- **Индикаторы** — точка без текста, смысл в тултипе: работает — серая пульсирующая, требует внимания — синяя статичная, ошибка — красная.
- **Кнопки.** Главная синяя — одна на экран. Вторичные — `#272727`, 28px. Иконки-кнопки — фон только при наведении. Круглые — только в поле ввода.
- **Выбор:** радио-карточки, чекбоксы и поля — раздел 07. Взаимоисключающий выбор — переключатель, раздел 05. Выпадающие списки — только кастомные, раздел 06.
- **Обратная связь:** тултипы, баннеры, серый прогресс — раздел 11.

Строительные блоки, которые уже есть в макете «Задача» и в чате:

| Блок | Где нарисован | Используем для |
|---|---|---|
| **Строка события**: моно 12px, глиф слева, текст, мета справа (`✎ src/auth/policy.ts +86 −4`, `$ npm run lint ✓ 4с`) | Задача, лента | правки, команды, субагенты, прочие инструменты |
| **Свёрнутая строка**: 11.5px `#6f6f6f`, шеврон, по клику раскрывается («Прочитал 6 файлов · поиск …») | Задача, лента | группа чтения, размышления, служебные строки |
| **Плашка** `#202020`, радиус 10 («План агента», «в фоне», «Агент закончил…») | Задача, лента | план, фоновые задачи, итог хода |
| **Карточка решения** `#1a1a1a` / `#202020`, радиус 10, кнопки 28px справа внизу (вопрос; «Обновить architecture.md», «ADR-0007») | Задача, Чат | вопрос, запрос разрешения |
| **Итоговая строка** после решения («Создан этап M01… Открыть») | Чат | свёрнутые вопросы и разрешения |
| **Мини-дифф** моно 12px: зелёный «+», приглушённый контекст | Чат, карточка документа | раскрытие правки файла |
| **Баннер** одного цвета с действием и крестиком | Инвентарь, 11 | авторизация, лимит, загрузка агента |

Общий принцип ленты: **всё, что ждёт пользователя, — карточка; всё, что уже случилось, — строка.** Решённая карточка сворачивается в итоговую строку.

## 1. Изменения в уже нарисованных блоках

### 1.1 Сообщение пользователя — состояние «в очереди»
Сообщение, отправленное во время работы агента, агент подхватывает не сразу, а после текущего шага.
- Нарисовать: тот же пузырь `#1c2a4d`, приглушённый (прозрачность), под ним 11.5px `#7d7d7d` «в очереди». Тултип: «Агент прочитает после текущего шага».
- Когда агент подхватил сообщение, пузырь становится обычным.

### 1.2 Текст агента
За один ход агент пишет несколько реплик: промежуточные («Разбираюсь в текущей авторизации…») и итоговый ответ.
- Стиль текста не меняется. Кнопка «Скопировать» — **только под итоговым ответом хода**, под промежуточными её нет.

### 1.3 Группа «Прочитал 6 файлов · поиск `requireRole`»
- Формула строки: `Прочитал N файлов · искал «…» · открыл N страниц`. Показываются только непустые части: к чтению и поиску в коде добавились поиск в сети и открытие страниц.
- **Нарисовать раскрытое состояние:** список строк событий без глифа — путь (цвет ссылки `#7d9ce8`, кликабелен) и мета справа: `строки 40–120`, `12 совпадений`, `docs.stripe.com`.

### 1.4 План агента — переезжает над поле ввода
Агент ведёт план не всегда, а только на многошаговых задачах, и обновляет его много раз за запуск. Поэтому план — одна обновляемая плашка, закреплённая **над полем ввода** (по ширине поля ввода), а не блок в потоке.
- **Свёрнуто** (по умолчанию): одна строка — пульсирующая серая точка, `ПЛАН · 2 / 5`, текст активного шага («Проверяю права в сервисном слое»), шеврон вверх.
- **Раскрыто:** плашка раскрывается вверх, список шагов — как сейчас. Больше ~8 шагов — прокрутка внутри.
- **Нет плана** — плашки нет.
- **Ход закончился** — плашка уходит из зоны над полем ввода. В ленте на её месте остаётся свёрнутая строка «План · 5 / 5 выполнено» (раскрывается списком).

### 1.5 Правка файла `✎`
Агент правит файл кусками, по одному файлу бывают десятки правок подряд. В ленте подряд идущие правки одного файла — **одна строка** с суммой `+/−`.

Варианты строки (глиф `✎`, путь, мета):

| Состояние | Мета справа |
|---|---|
| изменён | `+86 −4` (зелёный / красный, как на Обзоре) |
| создан | `новый · +120` |
| удалён | `удалён` |
| переименован | путь `old → new`, мета `переименован` |
| отклонён пользователем | текст приглушён и зачёркнут (как «Отменена»), мета `отклонено` |
| не применился | мета `не применилось` красным |
| ждёт разрешения | синяя точка вместо меты (см. 2.1) |

- **Раскрыто:** мини-дифф как в карточке документа чата, до ~12 строк.

### 1.6 Команда `$`
Данные у агентов разные: у Codex есть код выхода, длительность и живой вывод. У Claude Code — только «успех / ошибка», вывод приходит целиком в конце, зато есть описание команды человеческим языком.

- Строка: `$ npm test -- policy`. Под ней, если есть, описание — 11.5px `#7d7d7d`, Nunito: «Запускает тесты политики доступа».
- Мета справа по состоянию:

| Состояние | Мета |
|---|---|
| выполняется | серая пульсирующая точка + таймер `0:12` |
| успех | `✓ 4с` |
| ошибка | `✗ код 1` красным; если кода нет — просто `✗` |
| прервана | `прервана` |
| ждёт разрешения | синяя точка (см. 2.1) |

- **Раскрыто:** вывод в блоке `#1a1a1a`, радиус 8, моно 12px, максимальная высота ~240px с прокруткой и ссылкой «Показать всё».
  - Пока команда выполняется: у Codex вывод дописывается вживую, у Claude в раскрытии — «Вывод появится после завершения» и таймер.
  - ANSI-цвета терминала приводятся к палитре: красный → `#ef6a63`, зелёный → «+»-зелёный, жёлтый → `#e0a33c`, остальное — цвет текста.

### 1.7 Вопрос агента
Реальный формат: **от 1 до 4 вопросов за раз**. У каждого — короткий заголовок (до 12 символов), 2–4 варианта с пояснением, возможен множественный выбор и «свой вариант». У варианта может быть превью (фрагмент кода или макета). Бывает секретный ввод (например, токен).

Карточка — та же, что сейчас (`#1a1a1a`, радио с пояснением), плюс:
- **Заголовок вопроса** — меткой раздела (11px / 600, верхний регистр, `#6f6f6f`), например `СПОСОБ ПРОВЕРКИ`.
- **Несколько вопросов** — шаги внутри одной карточки: справа в строке заголовка `1 из 3` и иконки-кнопки ‹ ›. «Ответить» (синяя) активна, когда отвечены все.
- **Множественный выбор** — чекбоксы из раздела 07 вместо радио.
- **Свой вариант** — последняя строка вариантов: радио (или чекбокс) + поле из раздела 07 с плейсхолдером «Свой вариант…».
- **Секретный ввод** — поле с маской и иконкой «показать».
- **Превью варианта** — под списком вариантов блок `#0f0f0f`, радиус 8, с превью выбранного варианта.
- Подпись «Можно ответить своими словами в поле ниже» остаётся. Поле ввода в это время отвечает на всю карточку целиком (см. 3.1).
- **После ответа** — итоговая строка: «Ответ: Явно в сервисах», по клику раскрываются все вопросы и ответы.

### 1.8 Фоновая команда «в фоне · 2:14»
Фоновая команда (dev-сервер, watch-тесты) живёт параллельно с агентом и может пережить конец хода.
- Активные фоновые задачи закрепляются **над полем ввода**, в той же зоне, что и план: компактные плашки, как сейчас, с кнопкой «Остановить».
- В ленте в момент запуска — строка события `$ npm run test:watch`, мета `в фоне`.
- Раскрытие плашки — вывод (как в 1.6).
- Завершилась — точка статичная серая, мета `завершена · 5:02`, через несколько секунд плашка уходит. Остановлена — `остановлена`.

### 1.9 Итог хода «Агент закончил · 7 файлов · 4:36 · 41k токенов»
Есть в макете. Нужны варианты той же плашки:

| Вариант | Содержимое |
|---|---|
| Задача, успех | «Агент закончил · 7 файлов · 4:36 · 41k токенов» |
| Чат, успех | «Готово · 0:48 · 12k токенов» |
| Остановлено пользователем | «Остановлено · 2:11» |
| Ошибка | иконка и текст красным: «Запуск прервался: закончился лимит» / «нет авторизации» / «агент завершился с ошибкой», действие «Перезапустить» |

## 2. Новые блоки

### 2.1 Запрос разрешения — главное, чего нет
Появляется почти в каждом запуске. В режиме «Спрашивать» — на каждую правку и команду. В режиме «Авто в пределах задачи» — на всё за пределами ветки задачи, сеть и установку пакетов. Строка «Разрешить установку stripe@17?» на доске — это как раз он. Пока запрос открыт, статус задачи — «Нужен ответ».

Карточка — скелет карточки вопроса:
- **Заголовок** 13px: «Разрешить команду?» / «Разрешить запись файла?» / «Разрешить доступ в сеть?» / «Разрешить действие?».
- **Что:** команда моноширинно кораллом (`npm install stripe@17`), или путь (цвет ссылки), или хост (`api.stripe.com`).
- **Почему** — если агент объяснил: 12.5px `#a6a6a6` («Нужен SDK платёжного провайдера»).
- **Кнопки справа:** вторичная «Запретить» · вторичная «Разрешить до конца задачи» (в чате — «до конца чата») · главная «Разрешить».
- «Запретить» раскрывает в карточке поле «Почему? Агент увидит ответ» и кнопку «Отправить». Можно не заполнять.
- **После решения** карточка исчезает, а у соответствующей строки события (команда или правка) появляется мета `разрешено` / `запрещено`.
- **Несколько запросов сразу** — карточки стопкой. Синяя кнопка только у первой, у остальных «Разрешить» вторичная.

### 2.2 Размышления агента
Показываем свёрнутыми.
- Свёрнутая строка: шеврон + «Думал 12 с». Пока идёт — серая пульсирующая точка + «Думает… 0:07».
- Раскрыто: текст 12.5px `#7d7d7d` с отступом слева, как у вложенного содержимого.
- Агент скрыл содержимое — «Думал 12 с · содержимое скрыто», без раскрытия.

### 2.3 Субагент
Агент поручает часть работы (обычно поиск по коду) субагенту. Раскрывается **внутри строки**.
- Строка события: глиф `↳`, текст — описание задачи субагента Nunito 12.5px («Найти все проверки ролей в сервисах»). Мета: пульсирующая точка + `0:40` пока работает, потом `14 действий · 0:40`.
- Раскрыто: под строкой контейнер `#1a1a1a`, радиус 10. Внутри — обычная лента из тех же блоков (группы чтения, строки событий, текст). В конце — итоговый ответ субагента.
- Субагент внутри субагента — тот же приём ещё на уровень глубже.

### 2.4 Служебные строки
Одним стилем — свёрнутая строка с маленькой иконкой, без карточек:

| Событие | Вид |
|---|---|
| Повтор запроса к модели | пульсирующая точка + «Повтор 2 из 10 через 8 с»; после успеха строка исчезает |
| Сжатие контекста | разделитель на всю ширину ленты (линия `#242424`, как разделитель в меню) с подписью по центру 11px `#6f6f6f` «Контекст сжат» |
| Действие запрещено правилом | мета у строки события `запрещено правилом` |
| Предупреждение от агента | иконка и текст 11.5px `#e0a33c` |

### 2.5 Прочий инструмент
Инструменты, у которых нет своего вида (MCP-серверы пользователя и т.п.).
- Строка события: глиф `⚙`, имя инструмента моноширинно, короткий фрагмент входа приглушённо. Мета: `✓` / `✗` / пульсирующая точка.
- Раскрыто: два блока `#1a1a1a` с метками «ВХОД» и «РЕЗУЛЬТАТ», моноширинно, обрезка по высоте.

### 2.6 Баннеры сессии
Баннеры раздела 11 над лентой (вверху колонки чата или задачи):
- **Нет авторизации** (жёлтый): «Claude Code не авторизован. Войдите в аккаунт, чтобы продолжить.» · «Как войти».
- **Лимит** (жёлтый): «Лимит Codex исчерпан до 18:00. Запуск продолжится после сброса.»
- **Загрузка агента** (нейтральный, текст `#a6a6a6`): Skaro при первом использовании агента скачивает его сам (~230 МБ). «Загружаю Claude Code · 84 из 230 МБ» + серый прогресс из раздела 11 + «Отмена». Тот же прогресс — в карточке агента в модалке (4.4).

### 2.7 Изображения
Откуда картинки берутся в ленте:
1. агент **посмотрел** картинку — скриншот, макет, иконку из проекта или приложенную пользователем;
2. **скриншот от инструмента** — например, агент открыл страницу в браузере через MCP и проверяет вёрстку;
3. **сгенерировал** — умеет Codex, картинка сохраняется в файл;
4. **картинка в тексте** агента (Markdown);
5. картинку **приложил пользователь**.

Как показывать. Все превью — плашка `#1a1a1a`, радиус 10, картинка вписывается целиком, без обрезки. Миниатюры — радиус 8, как у вложения в поле ввода (3.1).

| Откуда | Вид |
|---|---|
| Посмотрел | В строку группы чтения добавляется часть «посмотрел N изображений». В раскрытом списке строка с картинкой начинается с миниатюры 40px, мета справа — размер `1280×800` |
| Скриншот от инструмента | Под строкой `⚙` превью видно всегда, не только в раскрытии: ради него инструмент и вызывали. До ~360px по ширине, до ~240px по высоте. Несколько картинок — ряд миниатюр 72px, последняя с «+N» |
| Сгенерировал | Такое же превью. Под ним подпись 11.5px `#7d7d7d` (описание от агента), рядом иконка-кнопка «Показать в папке». Не получилось — служебная строка (2.4), например «Не удалось сгенерировать изображение: лимит» |
| Картинка в тексте, файл проекта | Превью на месте картинки в тексте |
| Картинка в тексте по внешней ссылке | Не загружается сама. Плашка «Изображение по ссылке · docs.stripe.com» и вторичная кнопка «Показать» |
| Приложил пользователь | Миниатюры 72px над текстом внутри пузыря |
| PDF | Без превью, строкой в группе чтения: «прочитал PDF · 12 стр.» |

- **Просмотр:** клик по любой картинке открывает её поверх экрана (затемнение и размытие как у модалок инвентаря). Вверху — путь моноширинно, «Показать в папке», крестик. Стрелки ‹ › переключают картинки текущего хода, Esc закрывает.
- **Состояния превью:** загрузка — скелетон той же формы. Ошибка — иконка и «Не удалось показать изображение».
- **Модель не принимает картинки:** у чипа картинки в поле ввода — жёлтая пометка и тултип «Эта модель не принимает изображения».

### 2.8 Живая строка «агент сейчас…»
Между событиями бывают паузы по 30–60 секунд: агент думает или генерирует большую правку. Без подсказки кажется, что всё зависло.
- Одна строка в самом низу ленты (над зоной плана), стиль свёрнутой строки с пульсирующей серой точкой: «Думает…», «Пишет ответ…», «Готовит правку `src/auth/policy.ts`…», «Ждёт ответа модели · 0:12».
- Строка одна, не копится, пропадает при следующем событии.

### 2.9 Форматирование текста агента
Агент отвечает Markdown.
- **Блок кода:** плашка `#1a1a1a`, радиус 8, моно 12px, метка языка 11px сверху слева, иконка-кнопка «Скопировать» при наведении. Подсветка синтаксиса — приглушённая, из оттенков палитры. Синий не использовать (он только для кликабельного). Добавить в инвентарь как элемент «Подсветка кода».
- **Таблицы и Mermaid** — как на экране «Документы».
- **Ссылки:** `src/a.ts:42` — цвет ссылки, клик открывает файл в редакторе на строке. Внешний URL — ссылка с адресом в тултипе.

### 2.10 Агент сам сменил модель
Служебная строка (2.4): «Модель переключена на Sonnet 5». Кнопка модели в поле ввода тоже обновляется.

### 2.11 Команда ждёт ввода
Команда задала вопрос в терминале (`Proceed? (y/n)`). Агент ответить на него не может, и команда висит.
- Мета строки команды — синяя точка + «ждёт ввода · 0:40».
- В раскрытии: вывод с последней строкой-вопросом, подсказка «Команда ждёт ввода с клавиатуры — агент не может ответить» и вторичная кнопка «Остановить команду».

### 2.12 MCP-серверы пользователя
- **Не запустился:** служебная строка жёлтым «MCP-сервер linear не запустился» · «Подробнее».
- **Требует входа:** карточка решения «Сервер linear просит войти», кнопки «Пропустить» · «Войти» (открывает браузер).
- **Прислал форму:** карточка вопроса с полями раздела 07 (текст, число, выбор, флажок), кнопки «Отклонить» · «Отправить».

### 2.13 Восстановление после перезапуска Skaro
- **Получилось:** разделитель, как «Контекст сжат», с подписью «Сессия восстановлена».
- **Не получилось:** плашка итога хода, текст жёлтым «Не удалось продолжить сессию», действие «Начать заново с описанием задачи».

### 2.14 Откат, повтор, редактирование
- При наведении на сообщение пользователя появляются иконки-кнопки «Изменить» и «Откатить к этому сообщению». Под итоговым ответом рядом со «Скопировать» — «Повторить».
- **Изменить:** текст правится прямо в пузыре, «Отмена» · «Отправить». Это откат к сообщению и повторная отправка.
- Откат и повтор — через модалку подтверждения из инвентаря: «Откатить к этому сообщению? Изменения файлов после него будут отменены, сообщения ниже скрыты».
- После отката в ленте разделитель «Откат к сообщению · 14:32».

### 2.15 Режим «сначала план»
Агент изучает код, предлагает план и ждёт одобрения до правок.
- **Включение:** переключатель «Сначала план» в модалке агента с пояснением «Агент изучит код и предложит план до правок». Когда включено, в панели поля ввода — пилюля «План» в стиле кнопки модели.
- **Карточка решения «План агента»:** текст плана Markdown (свёрнут до ~10 строк, «Показать весь»), кнопки «Доработать» (раскрывает поле комментария) · «Одобрить» (синяя).
- После решения — итоговая строка «План одобрен» или «План отправлен на доработку».

### 2.16 Карточка слияния
Кнопок ревью и слияния нет. Пользователь пишет в чате задачи «вливай», агент запрашивает слияние, и в ленте появляется карточка — скелет карточки разрешения (2.1):
- заголовок «Влить в main?», под ним `skaro/T-020-admin-roles → main` моноширинно и `7 файлов · +214 −38`;
- если есть препятствия — строки жёлтым: «В main есть незакоммиченные изменения», «main ушла вперёд — агент обновит ветку», «Есть конфликты — агент их разрешит», «Изменения в .skaro/ будут отброшены»;
- кнопки «Отмена» · «Влить» (синяя). Пока есть блокирующее препятствие (незакоммиченные изменения в main), «Влить» неактивна;
- после слияния — итоговая строка «Влито в main · `a1b2c3d`», статус задачи «Готово»; отмена — итоговая строка «Слияние отменено».

## 3. Поле ввода

### 3.1 Состояния
- **Агент работает:** круглая кнопка «Стоп» (белая, как в инвентаре) видна всегда. Если в поле есть текст, слева от неё появляется синяя «Отправить». Сообщение уходит в очередь (1.1). Плейсхолдер — «Дописать агенту · Enter — отправить» (уже есть).
- **Открыт вопрос или разрешение:** плейсхолдер «Ответить своими словами…». Отправка = свободный ответ на открытую карточку.
- **Вложения:** над текстом — чипы в стиле кнопки модели (высота 28, радиус 999, фон `#383838`): иконка, имя (путь — моноширинно), крестик. Картинки — квадратная миниатюра 40px, радиус 8, с крестиком. «Прикрепить папку» добавляет чип-ссылку на путь, а не загружает содержимое.

### 3.2 Кнопка агента и модели в поле ввода
- В чате, где уже есть сообщения, агента сменить нельзя (решение владельца). Кнопка показывает модель, модалка открывается с заблокированным выбором агента (см. 4.1).

### 3.3 Меню «/» и «@»
- «/» открывает над полем ввода выпадающий список (раздел 06) с командами и навыками агента: имя моноширинно и описание. Список приходит от агента.
- «@» открывает выбор файла или папки проекта с поиском, путь моноширинно. Выбранное становится чипом, как вложение.

### 3.4 Контекст и лимит
- В панели поля ввода рядом с кнопкой модели — `72%` моно 11.5px `#7d7d7d`, тултип «Контекст заполнен на 72% — при заполнении агент сожмёт историю». От ~85% — жёлтым.
- Приближение к лимиту — жёлтый баннер (2.6): «Осталось ~10% лимита Claude до 18:00».

### 3.5 Режим прав на лету
- В панели поля ввода задачи — пилюля текущего режима («Авто») в стиле кнопки модели. По клику — выпадающий список из трёх режимов, смена применяется сразу, без перезапуска. Для «Полный доступ» — жёлтый, как в радио-карточке.
- В чате пилюли нет: там агент только читает код.

## 4. Модалка «Агент задачи» / «Агент чата»

### 4.1 Выбор агента
Карточки агентов — как сейчас. Добавить состояния карточки:
- готов;
- **не загружен** («Будет загружен при запуске · ~230 МБ»);
- **загружается** (серый прогресс);
- **не авторизован** (жёлтый текст «Войдите в аккаунт» и вторичная кнопка «Войти», которая открывает вход в браузере; если для агента вход из Skaro невозможен — ссылка «Как войти»);
- **недоступен в этом чате** (приглушена, тултип «Агента можно выбрать только в новом чате»).

### 4.2 Модель
Выпадающий список раздела 06 («сверху самые сильные, с пояснением») остаётся. Но названия и пояснения приходят от агента, а не зашиты:
- модель по умолчанию помечена «по умолчанию»;
- список длиннее ~7 пунктов прокручивается;
- **загрузка** — 3 скелетон-строки;
- **ошибка** — «Не удалось получить список моделей» + «Повторить».

### 4.3 Усилие
Ползунок усилия (решение владельца, см. «Инвентарь UI», «Ползунок усилия»). **Число шагов зависит от модели: от 2 до 5.** Подписи:

| Уровень | Подпись |
|---|---|
| minimal / low | Минимальное / Низкое |
| medium | Среднее |
| high | Высокое |
| xhigh | Очень высокое |
| max | Максимум |

Тултипы — пояснения от агента. Если модель не поддерживает выбор усилия, строка скрыта. Проверить, что 5 шагов читаются в модалке шириной 440px.

### 4.4 Режим прав и изоляция
- **Задача:** как сейчас, тексты верные.
- **Чат:** агент в чате проекта только читает код, поэтому «Режим прав» и «Изоляция» в модалке чата **не показываются**. Сейчас в макете чата режим прав есть — убрать.

## 5. Что сдать

Макеты в текущем формате, по состояниям:

1. **Лента задачи, агент работает, Claude Code:** группа чтения (свёрнута и раскрыта), правки файла во всех состояниях, команды во всех состояниях (одна раскрыта), размышление (свёрнуто и раскрыто), субагент (свёрнут и раскрыт), прочий инструмент, карточка запроса разрешения, зона над полем ввода с планом (свёрнут и раскрыт) и фоновой задачей.
2. **То же для Codex:** команда с живым выводом и кодом выхода.
3. **Вопрос:** один вопрос; три вопроса шагами; множественный выбор; свой вариант; секретный ввод; превью варианта; итоговая строка после ответа.
4. **Разрешение:** команда, запись файла, сеть; «Запретить» с полем причины; несколько запросов стопкой; строка события после решения.
5. **Концы хода:** успех в задаче, успех в чате, остановлено, три вида ошибки. Строка повтора и разделитель «Контекст сжат».
6. **Поле ввода:** агент работает + текст в поле; пузырь «в очереди»; чипы вложений и миниатюра; плейсхолдер при открытом вопросе.
7. **Модалка:** для задачи и для чата (без режима прав и изоляции, агент заблокирован); список моделей — загрузка, ошибка, длинный; ползунок усилия на 2, 3 и 5 шагов; карточки агента — не загружен, загружается, не авторизован.
8. **Баннеры:** авторизация, лимит, загрузка агента.
9. **«Инвентарь UI», раздел 10 «Чат и поле ввода»:** дополнить новыми элементами — карточка разрешения, вопрос с шагами и чекбоксами, строки событий во всех вариантах, строка размышления, субагент, служебные строки, зона над полем ввода, чипы вложений.
10. **Изображения:** «посмотрел» в группе чтения (свёрнуто и раскрыто); скриншот от инструмента — одна картинка и ряд с «+N»; сгенерированная картинка и ошибка генерации; картинка в тексте — локальная и по внешней ссылке; миниатюры в пузыре пользователя; просмотр поверх экрана; загрузка и ошибка превью; чип картинки для модели без поддержки изображений.
11. **Живая строка и текст агента:** все формулировки живой строки; блок кода с подсветкой и копированием; таблица; Mermaid; ссылки `путь:строка` и внешние.
12. **Служебное:** смена модели агентом; команда ждёт ввода; MCP — не запустился, требует входа, форма; сессия восстановлена и не восстановлена.
13. **Откат, повтор, редактирование:** иконки при наведении, редактирование в пузыре, модалка подтверждения, разделитель после отката.
14. **Сначала план:** переключатель в модалке, пилюля в поле ввода, карточка плана (свёрнута и раскрыта, «Доработать» с полем), итоговые строки.
15. **Поле ввода:** меню «/» и «@»; индикатор контекста (обычный и жёлтый); баннер приближения к лимиту; пилюля режима прав с выпадающим списком; кнопка «Войти» у карточки агента.

## 6. Чего не делать

- Не показывать названия инструментов агента (`Bash`, `Edit`, `Grep`) — только человеческие формулировки и глифы.
- Не добавлять аватары агента, время у каждого сообщения, счётчики токенов у реплик. Время и токены — только в итоге хода.
- Не показывать сырой JSON нигде, кроме раскрытия «прочего инструмента».
- Не вводить новые цвета, радиусы, тени и шрифты. Нужно новое — сначала в инвентарь, в том же стиле.
