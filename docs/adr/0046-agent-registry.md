# ADR-0046: адаптер агента и единственная регистрация

- Статус: принято.
- Дата: 31.10.2026.
- Основание: поручение владельца выполнить рефакторинг без изменения UI и
  поведения Claude Code и Codex; новых агентов не добавлять.
- Уточняет D-05, D-20, D-21 и D-23.

## Контекст

Общий `AgentAdapter` изолировал протокол общения, но список агентов повторялся
в core, IPC, запуске worker, восстановлении истории, UI и обновлениях.
Проверки «Codex или Claude» могли ошибочно интерпретировать неизвестный ID
как Claude. Добавление адаптера требовало менять общие контроллеры.

## Решение

`packages/agents/src/registrations.ts` — единственная точка подключения.
Пакет каждого адаптера экспортирует `AgentDefinition` через `./definition`.
Контракт находится в `packages/timeline/src/agent-definition.ts` и содержит:

- сериализуемые название, логотип и размеры из текущего UI;
- закреплённые версии CLI/SDK, версию пакета и версию проекции;
- описание npm-дистрибутива для платформы, размер загрузки;
- возможности сессии, политику проверки sandbox чата, имена файлов инструкций;
- имена инструмента вопросов и совместимые имена probe/диагностики;
- отдельные ленивые загрузчики runtime и проектора истории.

Реестр валидирует определения и выводит `AgentId` из зарегистрированных ID.
Отдельных union-типов, списков подключения в worker и выбора проектора нет.
Неизвестный ID явно отклоняется; сохранённые данные не переписываются и
другой агент вместо него не запускается.

`AgentManager` управляет установкой, кешами и состоянием готовности через
единый контракт. Авторизация, config-dir, CLI/SDK и нативные особенности
остаются в адаптере. Межпроцессное состояние авторизации выделено на агента.
Native worker получает ID и общие параметры, затем создаёт сессию через
реестр. Контроль принадлежности процесса, отмена, маскирование секретов,
запись сырого потока и MCP-права сохраняются на прежних границах.

Для replay используется проектор из того же пакета адаптера. При наличии
метаданных сегмента передаются его ID агента и версия адаптера; старые логи
без сегментов используют ID сохранённой сессии. Текущие проекторы сохраняют
прежнюю обработку нативных форматов. Поддержка несовместимой старой версии
формата — ответственность пакета адаптера, а не общего reader.

Renderer получает каталог через `agents.catalog` до монтирования UI.
`@skaro/agents/catalog` содержит только данные и функции поиска; runtime-импортов
реестра, Node и SDK в нём нет. Уже существующий renderer preview получает
те же настоящие метаданные при сборке Vite; preview не используется как
подтверждение штатной работы приложения.

## Совместимость

ID `claude-code` и `codex`, пути установок, закреплённые версии, нативные
сессии, настройки и сырые журналы сохраняются. UI-порядок остаётся Claude,
Codex; порядок компонентов обновления — Codex, Claude. SVG-пути, цвета,
размеры и тексты сохраняются из baseline.

Формат release manifest остаётся `schema: 1`. Поле `claudeSdk` сохраняется
как объявленный адаптером совместимый alias закреплённой версии; общие
сборочные скрипты и updater обрабатывают такие поля через реестр. Состав
агентов, версии пакетов адаптеров и проверки SDK формируются автоматически.
Integrity, закрепление версий, проверка всех шести платформ и порядок
публикации не ослабляются. Изменение схемы manifest этим ADR не вводится.

## Границы расширения

Новый агент требует пакета адаптера с полным определением и одной записи в
`registrations.ts`, а также обычного подключения workspace-зависимости и
обновления lockfile. Общие контроллеры, worker, UI и release-скрипты при этом
не получают ветвей по ID нового агента.

Контракт рассчитан на текущий workflow Skaro и установку закреплённого npm
дистрибутива. Продолжение сессии и compact обязательны. Возможности должны
соответствовать реальному runtime; отсутствие необходимой операции нельзя
маскировать успешным no-op. Новый транспорт установки или новое продуктовое
поведение требуют отдельного расширения контракта. Отсутствующий дизайн
состояния остаётся design gate и этим ADR не согласовывается.

## Проверка

Проверяются реестр и неизвестные ID, каталог, версии и платформенные пакеты,
совместимость manifest v1 и текущие правила выбора агента. Для запуска,
истории и UI используется только штатное приложение и настоящие агенты.
Mock API, временные серверы и подменённые ответы не создаются.

### Результаты проверки 31.10.2026

- Штатная `pnpm build`, проверка типов затронутых пакетов, ESLint и Prettier
  прошли; Svelte — без ошибок и предупреждений.
- 25 целевых тестов реестра, выбора агента, файлов инструкций и совместимости
  manifest v1 прошли. Полный suite не запускался.
- Четыре настоящие сохранённые истории дали одинаковые события при прямом
  создании прежних проекторов, выборе через реестр и фоновом replay;
  восстановление снимков также совпало.
- Browser-проверка штатного Electron с изолированной копией настоящего
  проекта прошла для настроек с загруженными моделями/config и для Codex:
  ответ через worker, сохранение журнала, восстановление после перезапуска
  приложения и продолжение той же нативной сессии. Компоновка просмотрена
  визуально; SVG-пути и размеры сверены с baseline.
- Новый probe находит настоящие закреплённые бинарники: Claude Code 2.1.285
  и Codex CLI 0.159.2. Остановка Codex через реестр проверена успешно.
- В изменённом исходном коде нет файлов больше 300 строк или Svelte-компонентов
  больше 180 строк. Новые агенты и продуктовые UI-состояния не добавлялись.

По прямому указанию владельца от 31.10.2026 живая генерация, resume и
остановка Claude пропущены в текущей проверке. Anthropic требует верификацию
аккаунта; повторная генерация и обход этого ограничения не выполняются.

Вместо повторной живой проверки дополнительно проверено без генерации:

- Фабрика реестра создаёт экземпляр прежнего `ClaudeAdapter`, версия
  адаптера совпадает с зарегистрированной.
- Настоящий закреплённый CLI подтверждает установку и статус входа;
  через адаптер получены 11 моделей, 65 команд, 4 MCP-сервера, 13 навыков
  и 0 хуков. Каталог настроек совпадает с разрешённым runtime каталогом.
- Все 8 доступных настоящих историй Claude из копии реального профиля
  воспроизведены напрямую, через реестр и через фоновый reader с точным
  совпадением событий. Всего проверено 6 569 событий и 12 сегментов,
  включая 3 открытых вопроса и 16 запросов разрешений. Восстановленные
  снимки совпадают с исходными состояниями ленты.
- По Git подтверждено отсутствие изменений в прежних `adapter.ts`,
  `session.ts`, `session-options.ts`, `session-config.ts` и
  `session-interrupt.ts` Claude.

Успешная живая генерация и resume Claude этими проверками не подтверждаются.
Ранее проверка остановки получила `Claude did not acknowledge interruption`;
тот же результат воспроизведён при прямом создании `ClaudeAdapter` без
реестра. Это наблюдение сохраняется; повторная проверка остановки пропущена
по указанию владельца. Заглушки и подменённые ответы не использовались.
