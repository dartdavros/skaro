# ADR-0047: встроенный агент Skaro и подключаемые модели

- Статус: принято; BA-1 — контракты, BA-2 — ядро lifecycle, BA-3 — инструменты Windows;
  полная приёмка не закрыта.
- Дата: 31.10.2026.
- Основание: поручение владельца сделать встроенного агента основным,
  оставить Claude Code/Codex альтернативами, поддержать BYOK, самостоятельно
  выбирать проверки и исправлять ошибки до сдачи результата.
- Пересматривает D-02 и D-03; расширяет D-05 и ADR-0046.
- Порядок реализации и приёмки: [план](../builtin-agent-plan.md).

## Контекст и цель

Внешние агенты имеют разные протоколы, инструменты и способы восстановления.
Реестр ADR-0046 унифицирует подключение, но не делает их runtime одинаковыми.
Встроенный агент должен использовать состояние проекта Skaro, сохранять
доказательства работы и доводить задачу до проверенной сдачи.

Преимущество оценивается по качеству принятого результата, числу исправлений
после ревью, времени и стоимости. Встроенность сама по себе не доказывает
превосходство модели или harness. Возврат фазового workflow v1 не вводится.

## Решение: границы ответственности

Skaro владеет задачами, общей очередью, worktree, окружениями, подтверждениями,
приёмкой и слиянием. Runtime владеет ходами модели и исполнением инструментов.
Завершение ответа модели не равно завершению задачи. Продолжение незавершённой
задачи идёт через существующий [процесс завершения](../completion-process.md);
независимого автопродолжения в обход очереди, остановки или решения владельца нет.

Runtime — модульный TypeScript-пакет без зависимости от renderer/Electron UI,
запускаемый отдельным процессом через адаптер и существующий native worker.
PID и принадлежность процесса фиксируются до допуска действий. Отдельный
процесс не заменяет sandbox. Направление зависимостей:
адаптер → runtime → контракты; доступ к сервисам Skaro — через узкие host-порты.

| Модуль runtime   | Ответственность                                                |
| ---------------- | -------------------------------------------------------------- |
| Session/loop     | Ходы, send/steer, вопросы, отмена, переходы между шагами       |
| Context          | Инструкции, отбор истории, ссылки на документы, compact        |
| Journal/recovery | Сохранение фактов и восстановление без повторных эффектов      |
| Tools/policy     | Схемы, допуск, права, исполнение и результаты инструментов     |
| Providers        | API, streaming, capabilities, continuation, usage и ошибки     |
| Verification     | План проверок, доказательства, актуальность и цикл исправлений |

Общий план проекта и короткий рабочий план одной задачи имеют разные области.
Статусы, документы и слияния не реализуются заново внутри runtime.

## Подключение, производитель модели и маршрут

Производитель модели, сервис доступа к API и фактический исполнитель запроса
не являются одной сущностью. Семейство Claude доступно напрямую у Anthropic
или через шлюз; это разные маршруты одного встроенного агента.

- `Connection`: устойчивый ID подключения, тип коннектора, endpoint/API-профиль,
  ссылка на credential, несекретные настройки и политика маршрутизации.
- `Model`: ID в каталоге данного подключения; производитель и семейство —
  отдельные метаданные. Глобальное равенство моделей по короткому имени запрещено.
- `Route`: connection ID + точный model ID + параметры + политика выбора
  upstream. Запрос хранит снимок маршрута и ревизии конфигурации без ключей.
- Ответ сохраняет фактическую модель, upstream, request ID и расход, когда
  сервис их сообщает. Отсутствующие данные остаются неизвестными.

Первая очередь включает прямые подключения OpenAI, Anthropic, DeepSeek и
OpenRouter как обязательный случай шлюза. Архитектура не ограничена этими
четырьмя сервисами. Несколько подключений одного типа и дополнительные
совместимые endpoint поддерживаются через конфигурацию и проверенный API-профиль;
новая семантика API требует коннектора, а не ветвей в общем loop.

| Подключение      | Исходный API-профиль | Особенности внутри коннектора                          |
| ---------------- | -------------------- | ------------------------------------------------------ |
| OpenAI direct    | Responses            | Output items, continuation, native compaction, usage   |
| Anthropic direct | Messages             | Tool-use/result blocks, thinking, cache и stop reasons |
| DeepSeek direct  | Chat Completions     | Thinking/reasoning_content и собственные ограничения   |
| OpenRouter       | Chat Completions     | Каталог, reasoning_details, upstream routing и usage   |

Поддержка дополнительных форматов Responses/Messages у DeepSeek и OpenRouter
не подразумевается одним совпадением схемы. Профили добавляются после реальной
контрактной проверки. Общий HTTP/stream transport допустим; семантические
коннекторы остаются раздельными. Версии SDK и API-профилей закрепляются релизом.

Capabilities определяются для маршрута и конкретной модели: tools, изображения,
reasoning, ограничения контекста/вывода, параллельные вызовы, cache и continuation.
Запись в каталоге — свидетельство возможностей, не доказательство их работы.
Необходимая операция при несовместимости завершается явной ошибкой; параметр
не удаляется молча, а отсутствие операции не маскируется успешным no-op.

У OpenRouter отдельно учитываются upstream allowlist, fallback и требования
к параметрам/обработке данных. Для обязательных параметров используется
`require_parameters`; fallback не расширяет согласованную политику. По умолчанию
Skaro не включает автоматическую смену модели, подключения или upstream;
разрешённая владельцем маршрутизация шлюза фиксируется в снимке запроса.

Модель и маршрут меняются между безопасными границами шагов: без исполняемого
инструмента и неразрешённого взаимодействия. Передаются общие факты и актуальный
контекст. Native continuation не считается переносимым между маршрутами.
Автоматический выбор дешёвой модели или отдельного ревьюера в первую очередь
не входит. Исчезновение модели из каталога не подменяет сохранённый выбор.

## Сессия, история и контекст

Адаптер реализует полный AgentSession: send, steer, respond, смену модели/прав,
resume, compact, interrupt, close и conversation rewind. Откат контекста
добавляет событие в журнал; исторические факты и исходные результаты сохраняются.
Файлы откатываются только существующим согласованным механизмом Skaro,
с защитой изменений владельца. Фоновые операции объявляются по реальной поддержке.

Один первичный версионированный журнал хранит факты сессии и native continuation
провайдера; лента, рабочий контекст и checkpoints — восстанавливаемые проекции.
Используются существующие контейнеры истории и проектор адаптера. Второго
независимого источника истины о ходе задачи не возникает.

У каждого вызова инструмента устойчивый ID. Намерение и допуск сохраняются
до действия, результат — до следующего запроса модели. После сбоя различаются
не начатое, завершённое и действие с неизвестным исходом. Неизвестный эффект
произвольной команды проверяется по фактам; автоматически повторять её нельзя.
Восстановление вопроса не исполняет инструмент повторно. Отмена закрывает
допуск новых действий, останавливает запрос/дочерние процессы и подтверждает
результат. Явная остановка сохраняется через перезапуск.

Контекст включает точные решения владельца, актуальные требования/ADR/C4,
инструкции применимой области, рабочую историю и ссылки на доказательства.
Данные репозитория, web и MCP не могут сами предоставить разрешение на действие.
Заметки модели сохраняют происхождение и не заменяют решения владельца.
Большие результаты читаются частями; skills и инструменты MCP подключаются
по области задачи и необходимости, без загрузки всего каталога в каждый запрос.

Compact создаёт новую рабочую проекцию, сохраняя цель, ограничения, открытые
вопросы и доказательства. Полная история не удаляется. Native reasoning/items
сохраняются в требуемом провайдером виде; их нельзя заменять обычным текстом,
произвольно редактировать или отправлять другому маршруту как совместимые.

## Инструменты и полномочия

Имена новых инструментов ниже рабочие, не утверждённые тексты интерфейса.

| Группа                                | Контракт                                                                |
| ------------------------------------- | ----------------------------------------------------------------------- |
| find_files/search_text/read_file      | Область, ignore-правила, диапазоны и продолжение выдачи                 |
| apply_patch                           | Точные изменения с проверкой исходного контекста и защитой чужих правок |
| exec_command/write_stdin/stop_process | Shell/cwd, streaming, stdin, timeout, exit code и доказанная остановка  |
| view_image                            | Реальные изображения при поддержке выбранного маршрута                  |
| ask_user/update_plan                  | Сохраняемые вопросы/решения и рабочий план задачи                       |
| run_check                             | Выполнение проверки с сохранением доказательств                         |
| Browser/MCP/skills                    | Существующий Playwright MCP и расширения с ограниченной областью        |

Схема, аргументы, права, отмена и ошибки проверяются на границе каждого вызова.
Параллельны независимые чтения; конфликтующие записи упорядочены. Произвольная
shell-команда не считается чтением по предположению. Полный длинный вывод
сохраняется, модель получает фрагмент со ссылкой на продолжение.

Продуктовые операции используют те же handlers, scopes и подтверждения, что
MCP Skaro: get_project_context/get_c4_context/read_task_history, предложения
документов и планов, окружения, review_c4, submit_result, report_task_blocker,
merge_task. Внутренний транспорт не даёт обхода этих проверок. Доступ файловых
и shell-инструментов ограничивается отдельно от MCP scope; каталог .skaro
изменяет существующий сервис артефактов.

Сохраняются режимы ask/auto/full и D-28: auto опирается на проверенную границу
sandbox, отсутствие границы не выдаётся за изоляцию. Права не отменяют прямые
ограничения владельца и design gate. Credentials хранятся в системном защищённом
хранилище; недоступность хранилища не разрешает plaintext fallback. Ключи,
auth headers и секреты не попадают в renderer-каталог, журнал, .skaro, Git
или общее окружение shell. Endpoint не получает credential другого подключения.
Отправка телеметрии/журналов отдельно от необходимых модельных запросов
не включается этим ADR.

## Самостоятельные проверки и исправления

Модель выбирает проверки из правил владельца/проекта, критериев, CI,
существующих тестов и фактических изменений. План связывает проверку с
требованием, способом выполнения, окружением и ожидаемым результатом.
Обычный выбор проверок в разрешённой области не требует нового подтверждения.

Объём соблюдает правила проекта: документация без build/runtime-тестов,
мелкие UI-правки без автоматической сборки, остальной код со сборкой и
значимыми затронутыми тестами, UI с browser-проверкой; полный suite только
перед релизом или по прямому указанию. Новые тесты покрывают значимое поведение.
Проверки используют штатное окружение. Mock API, fake backend, fixtures,
seed-данные и временные серверы без отдельного разрешения запрещены.

run_check и browser-проверки сохраняют ID, назначение, критерии, команду/сценарий,
cwd, ревизию окружения/инструментов, время, вывод, код/наблюдение и артефакты.
Снимок исходников учитывает tracked, dirty и untracked inputs; одного HEAD
недостаточно. После изменения входов затронутое доказательство устаревает;
при неизвестной зависимости актуальность не предполагается. Машинная проверка
доказывает исполнение и результат, но не полноту семантического покрытия.

Цикл: диагностировать → сформулировать причину → исправить → повторить упавшее
и затронутые проверки → сверить критерии и diff. Нестабильное падение остаётся
в истории даже после успешного повтора. Отключение тестов, ослабление требований
или подмена окружения ради зелёного результата запрещены. Исправление теста
требует основания в требованиях или доказанной ошибки самого теста.

submit_result использует ссылки на доказательства и существующий сервис
приёмки. Неисполненные/устаревшие обязательные проверки, открытые решения и
неактуальный необходимый C4-review возвращают конкретные причины для продолжения.
Изменение протокола сдачи не ослабляет альтернативных агентов и не создаёт
повторного общего прогона при слиянии: D-45 сохраняется.

Прогресс подтверждается изменениями и результатами диагностики. Повторы без
прогресса ограничиваются существующим процессом завершения; исчерпание бюджета,
явная остановка, конкретный вопрос или доказанный внешний блокер сохраняются
как причины незавершённости. Кодовые ошибки в области задачи агент исправляет
сам; несвязанные дефекты не расширяют область работ автоматически.

## Совместимость, поставка и открытые решения

Встроенный runtime поставляется и версионируется вместе со Skaro. Реестр
различает bundled runtime и скачиваемый закреплённый npm-дистрибутив; фиктивных
загрузок, подписки или квот для встроенного агента нет. Balance/usage BYOK
не преобразуются в пятичасовые/недельные окна Claude/Codex. Изменение публичной
схемы release manifest не утверждается: при необходимости оно проектируется
отдельно; проверки integrity и шести целевых OS/arch сохраняются.

Claude Code/Codex, их IDs, вход, настройки и сырые истории сохраняются.
Встроенный агент станет основным после приёмки, без переписывания сохранённого
выбора в проектах/задачах. Передача между агентами использует agent-handoff;
направление по умолчанию не разрешает скрытый fallback на другой агент.

Сейчас утверждён архитектурный контракт, не UI. Имена/логотип, настройка ключей,
подключений и routing, ошибки/возможности/расход требуют утверждённого дизайна.
До его появления зависимая UI-работа заблокирована; runtime можно реализовывать
и проверять через штатные предусмотренные проектом точки запуска.

В первую очередь входит один исполнитель. Субагенты, автоматический routing
между моделями, LSP, programmatic tool calling и отдельный агент-ревьюер —
последующие расширения после измерений. Точные пакеты, DTO, OS sandbox backend,
каталог моделей и бюджеты уточняются в соответствующих этапах плана.

## Источники и статус проверки

Документация API проверена 31.10.2026; доступность модели и поведения на
конкретном маршруте требует реальных проверок при реализации:

- [OpenAI: состояние разговора](https://developers.openai.com/api/docs/guides/conversation-state).
- [Anthropic: tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview).
- [DeepSeek: thinking и tool calls](https://api-docs.deepseek.com/guides/thinking_mode/).
- [OpenRouter: API](https://openrouter.ai/docs/api_reference/overview),
  [routing](https://openrouter.ai/docs/guides/routing/provider-selection) и
  [reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

BA-1 выполнен на уровне контрактов: [фактическая структура](../builtin-agent-contracts.md),
[результаты и ограничения](../builtin-agent-plan.md#результат-ba-1-31102026).
В BA-2 реализовано [ядро runtime](../builtin-agent-runtime.md), полная приёмка
ещё не закрыта. В BA-3 добавлены [инструменты](../builtin-agent-tools.md)
и Windows Job Object; проверенного filesystem/network sandbox нет, действует D-28.
Коннекторы, защищённое хранилище и UI отсутствуют;
живые модельные запросы и browser-проверки не выполнялись.
