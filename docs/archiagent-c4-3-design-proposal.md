# C4-3 — утверждённый макет полного аудита

Дата: 13.11.2026. **Макет утверждён владельцем; разрешена реализация C4-3.**
Утверждение: «Макет согласован, делай C4-3 по нему». Включены полное окно
`c4-audit-full-window.html` и явно запрошенные владельцем иконки Lucide.
Основание — поручение владельца «Подготовить макет на согласование» после
[проверки design gate](archiagent-c4-3-design-gate.md).
Это утверждённый дизайн, не доказательство реализации или приёмки C4-3.

## Основной сценарий

1. В существующей панели галереи C4, перед экспортом PNG, появляется одна
   вторичная кнопка **«Полный аудит»**. Фильтры, сброс, экспорт и переключатель
   списка/плитки сохраняются. При отсутствии модели остаются прежний Banner
   «Принятая модель C4 ещё не создана.» и доступный явный запуск аудита.
2. Первое нажатие начинает аудит через штатные права и ресурсный допуск,
   открывает существующее окно **«Фоновая работа»**. Дополнительного окна
   подтверждения запуска нет. Открытие проекта, раздела C4 или окна фоновой
   работы само по себе ничего не запускает.
3. Ход аудита занимает обычную строку текущей фоновой работы: название,
   конкретное состояние, пояснение и доступное действие. Кнопка C4 при активном
   запуске показывает общий спиннер; повторное нажатие открывает эту же работу,
   не создаёт параллельный аудит и не вызывает модель повторно.
4. Закрытие окна, переход на другую вкладку и Escape не останавливают аудит.
   Отдельная кнопка **«Остановить»** запрашивает безопасную остановку.
   До подтверждения остановки показывается «Останавливаем аудит…».
5. Существенное предложение сохраняется одним пакетом и одним решением.
   В фоновой работе находится только ссылка **«Открыть решение»**; действия
   **«Открыть» / «Отклонить» / «Применить»** остаются в существующей карточке
   общего окна **«Требуют ответа»** и в штатной закреплённой области чата.
   Это проекции одного ID, а не два независимых согласования.
6. Применение и его фактическая проверка отражаются в фоновой работе.
   Событие успеха появляется только после проверки записанных документов и C4.
   Для нового запуска после завершения предусмотрено отдельное явное действие
   **«Запустить заново»** в строке. Кнопка галереи открывает сохранённый итог.

## Источник и существующие представления

Предлагаемый источник — обычный проектный чат **«Полный аудит C4»**, создаваемый
только по явному запуску. Он хранит исходный запрос, evidence, результат и
историю; не является фиктивной продуктовой задачей. В карточке используются
существующие источник «Чат · Полный аудит C4» и переход «Открыть чат».
Для повторного запуска сохраняется прежняя история и отдельная идентичность run.

Кнопка «Открыть» ведёт в имеющийся просмотр точного архитектурного пакета.
«Журнал проекта» открывает существующий долговечный журнал AC-4. Эти экраны
не перепроектируются. В интерактивном предложении их полный UI не воспроизводится:
переход обозначен подписью вне изображаемого продукта.

Запросы прав, входа и других разрешений используют уже существующие карточки
и решения AC-4, с правильным источником и продолжением нужного run. Они не
подменяются C4-карточкой «Применить» и не получают новые формы в этом макете.
В чате ожидающее действие закреплено над вводом, включая восстановление
и пагинацию; новых вопросов среди истории не добавляется.

## Состояния, предлагаемые к утверждению

В строке работы название «Полный аудит C4» предшествует состоянию. Тексты
ниже — предлагаемые новые тексты, а не ранее утверждённый baseline.

| Состояние | Видимый текст | Действие |
| --- | --- | --- |
| До первого запуска | «Полный аудит» в панели C4 | Явный запуск; окно статуса ещё не открыто |
| Подготовка | «Подготавливаем аудит…» | Остановить |
| Выполнение | «Сверяем архитектуру с кодом…» | Остановить |
| Ресурсный допуск | «Ожидаем ресурсы для аудита» | Остановить; доступ не обходится |
| Доступ к модели | «Ожидаем доступ к модели» | Остановить; штатный запрос доступа сохраняется |
| Pending-пакет | «Запрошено решение владельца» | Открыть решение; подтверждений в строке нет |
| Применение принятого | «Применяем согласованные изменения…» | Остановить недоступно во время записи |
| Проверенный успех | «Аудит завершён» | Запустить заново; Открыть чат |
| Недостаточные evidence | «Сверка завершена не полностью» | Запустить заново; Открыть чат |
| Ошибка до применения | «Не удалось завершить аудит» + конкретная причина | Повторить; Открыть чат |
| Конфликт accepted | «Согласованный пакет не применён» + конкретный конфликт | Проверить применение; Открыть чат |
| Запрошенная остановка | «Останавливаем аудит…» | Повторная остановка недоступна |
| Подтверждённая остановка | «Аудит остановлен» | Запустить заново; Открыть чат |
| Восстановление | «Проверяем сохранённое состояние…» | Проверка фактического исхода без повторной записи |

Во время ожидания ресурсов/модели используется существующая иконка часов;
во время работы — общий LoadingIndicator; при ошибке — существующий error-стиль.
Процент выполнения не выдумывается. Пояснение называет причину ожидания/ошибки,
что сохранено и что произойдёт при доступном действии.

Успех без расхождений поясняется «Подтверждённых расхождений не обнаружено.
Открытые вопросы сохранены». После проверенного применения — «Согласованный
пакет применён. Открытые вопросы сохранены». Отклонение пакета показывается
как отклонение и отсутствие применения, не как отсутствие расхождений.
Неполные данные сохраняют неизвестность и открытые вопросы.

Конфликт accepted не возвращает пакет в pending и не просит принять его снова.
Пример в макете: модель изменилась после согласования, файл не перезаписан,
решение сохранено. «Проверить применение» перечитывает журнал и фактический
результат прежней операции; не запускает новый LLM-аудит и не разрешает
перезапись конфликта. Неустранённый конфликт остаётся видимым после проверки.

## Геометрия и визуальный язык

Используются текущие Button, Modal, LoadingIndicator, BackgroundRow,
DecisionCard и ArchitectureProposal; новый отдельный экран аудита не нужен.
Шрифт Nunito Sans, тёмные токены, размеры, радиусы, типографика и Lucide-иконки
берутся из текущего кода `renderer/src/` и `packages/ui/src/`.

По прямому поручению владельца кнопки действий в диалогах макета дополнены
иконками Lucide слева от текста: «Открыть» — `folder-open`, «Отклонить» — `x`,
«Применить» — `check`, просмотр «Смотреть» — `eye`, переход в чат —
`message-square`, журнал — `history`, повтор — `rotate-cw`, остановка —
`square`, проверка применения — `file-check-2`, «Позже» — `clock`,
«Закрыть» — `x`. Подписи и поведение сохраняются; размер иконок 16 px.
На момент этой правки иконки были разрешённым дополнением предложения;
затем владелец утвердил весь макет, как зафиксировано в начале документа.

После утверждения макета владелец отдельно уточнил кнопку «Остановить»:
уменьшить её и заменить контурную иконку сплошной. Разрешённое уточнение:
высота 24 px, горизонтальные отступы 9 px, шрифт 12 px; Lucide Square 12 px
с `fill=currentColor` и без обводки. Остальные действия сохраняют свои размеры.

- Окно фоновой работы сохраняет ширину 720, заголовок, подзаголовок
  «Cat-pilot · Сейчас и недавно», прежние секции и footer «Журнал проекта» /
  «Закрыть». Новая строка использует устойчивую область под статус и пояснение.
- Окно решений сохраняет ширину 720, область списка 480, источник карточки,
  карточку пакета и footer «Позже». Никаких подтверждений в двух окнах.
- При загрузке, ошибке и смене статуса размер окна не прыгает; заголовок
  и кнопка закрытия доступны. Длинный список использует штатный scroll Modal.
- Список/плитка и вся остальная галерея остаются по baseline. Предложение
  показывает фрагмент со списком, а не задаёт новый режим галереи по умолчанию.

## Восстановление и границы проекта

Состояние принадлежит проекту и run. Переключение проекта закрывает его окно,
не переводит решение в другой проект и не отменяет сохранённую работу.
Возврат открывает существующие состояние и решение, без нового запуска.
Остановленный владельцем аудит после перезапуска не возобновляется сам.
Прерванная запись сначала проверяется по журналу; неизвестный исход не
считается успехом и не повторяется вслепую.

Миграция сохраняет ID, байты пакета, fingerprints, источник, версию протокола,
pending/accepted и историю. Старое согласие не становится новым вопросом;
ответ из чата или общего окна продолжает ровно зависимые операции один раз.
Открытие C4 и независимая индексация графа не обращаются к LLM.

## Что проверено у предложения

Интерактивный макет содержит 14 примеров состояний, в том числе отдельный
конфликт принятого пакета. Его данные иллюстративны: это не результаты аудита
Cat-pilot. Локальные переходы показывают предлагаемый дизайн и ничего не
записывают в проект, API или backend. Временный HTTP-сервер не запускался.

В отдельном browser-просмотре макета проверены запуск одним нажатием,
закрытие без остановки, переход к одному решению, «Позже», применение,
остановка, повторное открытие без возобновления, отсутствие модели и конфликт
без повторного согласия. У 13 открытых состояний одинакова геометрия окна;
до запуска окно закрыто. На ширинах 1100/736/360/320 нет выхода элементов
за границы фрагмента и горизонтального переполнения. Проверены снимки.

Источник предложения: `c4-audit-proposal.html`, протокол browser-проверки:
`c4-audit-design-qa.json`; оба находятся в каталоге визуализаций текущего чата
`C:/Users/drmar/.codex/visualizations/2026/11/12/01a1d1f4-14e0-7e61-9ef2-f0a8e8592284/`.

Продуктовый код и данные Cat-pilot не изменены. Сборка Skaro, runtime-тесты
и реальная browser-приёмка приложения не выполнялись: проверен только дизайн.
Design gate закрыт явным утверждением владельца. Для завершения этапа
нужны реализация C4-3, сборка, целевые проверки, миграционная и реальная
browser-приёмка на Cat-pilot по [плану](archiagent-c4-plan.md).
