# Управляемое включение архиагента

AG-1 вводит owner API для одного зарегистрированного проекта. Отдельный UI
переключателя не добавлен. Совместимость форматов не означает прохождение всей
приёмки AG-1; её фактическая матрица находится в [отчёте](archiagent-ag1.md).

## Порядок

1. Получить `archiagent.status(projectId)`. Сверить проект, существующие решения,
   версии старых запусков и `compatible`. Сохранить проверенные долговечные
   SQLite-копии обеих БД перед миграцией/проверкой восстановления.
2. Вызвать `coordinator.setDispatch(projectId, false, dispatch.revision)`.
   Это fence новых dispatch и старых execution intents. Уже начавшийся внешний
   эффект не объявляется отменённым или несуществующим.
3. Снова получить status. Передать в `archiagent.activate` выбранный протокол
   будущих запусков, новый request ID и точные `dispatchRevision`,
   `activationRevision` (0 без receipt), текущий `protocol` и `eligibility`.
4. Один SQLite commit связывает protocol default, activation receipt и новое
   включение dispatch. При изменении входов запрос отклоняется целиком;
   требуется новая проверка состояния, а не подстановка старого fingerprint.

Receipt содержит coordinator ID, schema/feature versions, request hash и revision.
Неизвестная версия/формат блокирует новый dispatch. Безопасный off остаётся
доступен. Повтор того же request ID с теми же входами возвращает исходный
результат, пока включение не было остановлено. После off нужен новый owner intent.
Старый `c4.selectProtocol` и прямой legacy on не обходят управляемый барьер.

Ни activation, ни on не запускают backlog и не восстанавливают owner Stop.
Новый запуск получает выбранный default; существующий сохраняет свой binding.
Прежний запуск без binding остаётся package-v1. Разрешения, запреты, критерии,
пакеты и подтверждённые ответы при включении не переписываются.

## Остановка и совместимый откат

Для остановки используется тот же штатный off. Совместимый откат — новый цикл
off/status/activate с package-v1 в **поддерживающем эти форматы runtime**.
Существующие impact-v1 результаты и bindings продолжают читаться своим протоколом;
старый пакет не переинтерпретируется как новое разрешение.

Native Stop сначала закрывает attachment/transport и проверяет собственные
процессы по PID/birth. Только после этого подтверждённый host receipt завершает
старую owner delivery как остановленную и освобождает её writer. Старая команда
не повторяется; её журнал и возможные частичные результаты сохраняются. Stop
task runtime не подтверждает доставку, которой владеет integration resolver.
Ожидающие общие решения при остановке отдельного исполнителя не удаляются.

Новый код отклоняет future SQLite schema до настройки WAL/миграций. Это не
сертификация произвольного прежнего executable: бинарник, в котором таких
guards ещё нет, не получает их из нового receipt. Downgrade executable и выпуск
релиза требуют отдельной проверки по [release contract](updates.md).

## Проверенный контур

Живое включение ограничено Cat-pilot на Windows/Codex. Другие проекты не
восстанавливались и не включались этой приёмкой. Поддержка иных платформ,
адаптеров, конкурентного live-запуска двух проектов и оставшиеся сценарии не
подразумеваются успешным CAS или сборкой; см. открытую матрицу AG-1.
