# Skaro 2.2.21

Дата подготовки: 05.11.2026. Bundle и отображаемая версия: `2.2.21`.

## Исправление

После переноса файла в задаче C4 могла продолжать ссылаться на старый путь.
Проверки интеграции проходили, но публикация отклоняла тот же кандидат, после
чего Skaro повторял вливание и запускал resolver без устранения причины.

- Ссылки C4 на код и точные файловые evidence переносятся по переименованиям,
  обнаруженным Git. Семантика элементов и planned-область сохраняются.
  Удаление без переименования не получает выдуманного пути и остаётся ошибкой.
- C4 проверяется перед готовностью кандидата и повторно при публикации.
  Файлы локальных слоёв не могут подменить отсутствующие файлы публикуемого дерева.
- Ошибка C4 прекращает автоматические попытки и отменяет подтверждение готовности.
  Существующее сообщение об успехе публикации появляется после успешного вливания.
- Уже проверенный кандидат, остановившийся на старой ошибке отсутствующего пути,
  восстанавливается только после повторного допуска Git и полной проверки C4.
- Область task review включает обе стороны переименования. C4 и код публикуются
  одной Git-транзакцией; принятые результаты задач не переписываются.

UI, pins агентов, SDK, адаптеры и lockfile не меняются.

## Доказательства

- На реальной сохранённой интеграции старый валидатор воспроизвёл две ошибки
  `identity/models.py`; исправленный перенёс обе ссылки в `identity/models/users.py`
  по Git-переименованию. Проверка выполнялась read-only, planned-область сохранена.
- По прямому указанию владельца сначала исправлена его текущая установка 2.2.20:
  собран новый main, сохранены исходный пакет и резервная копия БД. Побайтово
  подтверждена неизменность 954 остальных файлов пакета.
- Реальная операция восстановлена через штатные сервисы IntegrationService и
  CompletionCoordinator с ограничением БД/фоновых операций одним проектом.
  Кандидат и принятые результаты не менялись; сохранённые реальные build/behavior
  проверки повторно не выдавались за новый прогон. Операция стала `applied`,
  задача T-001 — `done`, код и C4 опубликованы вместе. Полная проверка путей C4
  опубликованного проекта вернула 0 ошибок. Число попыток агента не выросло.
- В открытой установленной программе визуально подтверждён статус «Готово».
  Старые ошибки сохранены в истории. Отдельная автоматическая UI-проверка
  Cat-pilot прервана завершением окна и не заявляется пройденной.
- Прошли production-сборка, desktop main TypeScript, целевые ESLint/Prettier,
  20 существующих интеграционных тестов, три новых регрессионных сценария,
  адресный C4 unit-тест и read-only проверка реального кандидата.
- Регрессии проверяют атомарное вливание с C4 после рестарта, отказ при удалении
  файла и отсутствие повторного resolver/ложного сообщения успеха при ошибке C4.
- Изменённые модули не превышают 300 строк. Новые обязанности разделены между
  подготовкой C4 кандидата, проверкой интеграции и восстановлением операции.

## Разрешение на выпуск

Владелец отдельно разрешил целевые тесты и полный штатный CI/release suite
с изолированными fixtures/HTTP test servers и переиспользование принятой проверки
неизменённых агентов для 2.2.21. Новые canary/model проверки не заявляются.

Выпуск по [контракту обновлений](updates.md): `check_scope=full`,
`test_fixtures_allowed=true`, `agents_verified=true`, после обязательного CI.
Описание релиза содержит таблицу шести установщиков Windows/macOS/Linux × x64/arm64.
