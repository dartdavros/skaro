# Внутренний запуск builtin-задачи через общую очередь

Дата: 02.11.2026. Часть BA-7; продуктовый picker и сквозная приёмка открыты.

`TaskRuns.launchBuiltin` — main-only вход для новой настоящей задачи. Он требует
явные route ID, permission mode, isolation, planFirst и текст с command ID.
Настройки внешнего агента и проекта не подставляются. Подготовка сверяет
сохранённые Connection/Route и актуальный каталог; ключ и model POST для
постановки в очередь не нужны. Само наличие маршрута не выдаёт model/tool grant.

Вход использует прежние TaskStartup, RunQueue и createTaskRun. Проверяются
существование задачи, архив, статус, зависимости и отсутствие прежнего run
или задания в очереди. Для начатой задачи остаётся продолжение/handoff.
Перед созданием run маршрут и ограничения задачи проверяются повторно.
Worktree, окружение, слоты и дальнейшая доставка используют общий lifecycle.

Выбор и вход сохраняются вместе с уникальной попыткой startup. Ошибка
подготовки сохраняет точный вход; повтор допускается с теми же command ID,
текстом и настройками. Отмена отзывает попытку, включая ожидание каталога,
очереди, подготовки checkout и сессии. Повторный выбор тех же настроек не
оживляет старую попытку. После отмены перед созданием run восстанавливается
прежний статус задачи; уже созданный checkout автоматически не удаляется.

Настройки builtin-run хранятся отдельно по run ID и сверяются с настоящим
неотозванным run. Изменение defaults внешнего агента не меняет права builtin.
Пропущенная запись после аварии между createRun и сохранением настроек
восстанавливается только из pending выбора до первого native session ID;
отсутствующее или несовместимое состояние даёт отказ.

Прерывание увеличивает поколение доставки и отменяет builtin startup.
Вход, ожидавший attachment, и остаток пакета не отправляются после остановки.
Запоздавший native process закрывается с отзывом admission. Возврат задачи
на доске сериализован с созданием run и перечитывает актуальный статус.

## Проверки и границы

- Целевые тесты: 4 файла, 9 тестов прошли — строгий DTO, реальные SQLite settings, сохранение входа и
  ошибки, точный повтор, отзыв и замена попытки; task/chat session policy и
  настоящий compiled native worker с допуском/отказом до model POST.
  Проект, задача, run и ответы модели в тестах не создаются и не подменяются.
- TypeScript main, lint, форматирование и production build прошли.
  Изменённые файлы не превышают 300 строк.
- UI не изменён. Положительный запуск новой builtin-задачи в Electron,
  handoff, submit_result и merge этим изменением не приняты.
- Живые workflow проверяются только на Cat-pilot. T-008 нельзя запускать
  в обход незавершённой T-006. Дополнительных model POST не выполнялось.
- Продуктовый AgentId/picker пока принимает managed-агентов; отображение и
  выбор builtin, а также общий положительный workflow остаются следующим шагом.
